```xml
    <httpEndpointPolicy name="ServiceNowProfile">
      <connectionUrl>https://yourinstance.service-now.com/api/now</connectionUrl>
      <authentication>
        <basic>
          <username>your_username</username>
          <password>your_password</password>
        </basic>
      </authentication>
    </httpEndpointPolicy>
  </policySet>
</policySets>
```

---

Use **Integration Toolkit** to make a simple test flow:

1. **Create a new Message Flow**.
2. Add:
   - An **HTTPInput** node
   - A **ServiceRequest** node (use your ServiceNow profile/policy)
   - An **HTTPReply** node
3. Configure the ServiceRequest node:
   - Method: `GET`
   - URL: `/table/incident?sysparm_limit=1`
   - Policy: `ServiceNowProfile` (from your policy project)
   - Response expected: `Yes`

4. Deploy this test flow to your integration server.

---

### 🚀 STEP 3: **Trigger the Flow**

You can test this via:

- **Postman**:

   - **`mqsireadlog`** and **`mqsiformatlog`**

## 🛠️ How to Add and Use the Trace Node in Your Flow

### ✅ 1. **Where to Place the Trace Node**

You can place the Trace node:
- **Before** the ServiceNow Request node — to trace the request payload and headers
- **After** the ServiceNow Request node — to trace the response and any faults

**Recommended setup:**
```
HTTP Input → Compute (optional) → Trace (before request) → ServiceNow Request Node → Trace (after request) → HTTP Reply
```

---

### ✅ 2. **Configure the Trace Node (Before ServiceNow Call)**

To see what you’re sending to ServiceNow:

1. Double-click the **Trace node**.
2. Set **Trace Destination** to:
   ```
   File
   ```
3. Set **Trace File** path:
   ```
   /tmp/trace_before.txt
   ```
   *(Or a valid directory on your system/integration server)*

4. Set **Pattern** to:
   ```text
   Input message before SNOW call: ${Root}
   ```

---

### ✅ 3. **Configure the Trace Node (After ServiceNow Call)**

To see what ServiceNow is returning:

1. Another Trace node → set **Trace File** path:
   ```
   /tmp/trace_after.txt
   ```
2. Use this pattern:
   ```text
   SNOW Response: ${Root}
   ```

This will capture both the response payload and faults (e.g., SOAPFault, JSON error).

---

### ✅ 4. **Deploy and Run**

Deploy your flow, invoke it, and then check the trace output:

```bash

cat /tmp/trace_after.txt
```

Look for:
- Missing fields
- JSON or XML structure issues
- ServiceNow error messages inside the response

If you expect an error, you can use a **Try-Catch node setup**:

```
TryCatch
```

Catch Trace pattern:

## 🔧 Node Purposes

### 🔶 **TryCatch Node**
- A **TryCatch node** lets you handle exceptions (like a 500 Internal Server Error) gracefully.
- It has **two paths**:
  - **Try** → main success path
  - **Catch** → executes only if an error occurs in Try

### 🔹 **HTTP Input**
- Receives the incoming HTTP request (e.g., from Postman or another system)

### 🔹 **Mapping Node**
- Maps incoming data to the required format for ServiceNow (e.g., sets `description`, etc.)

### 🔹 **Trace (Before SNOW)**
- Logs the structure/message before it reaches the ServiceNow Request node
- Helps verify what you are sending

### 🔹 **ServiceNow Request Node**
- Sends a request to create a record in the `em_event` table in ServiceNow
- Configured with policy, credentials, and action "Create"

### 🔹 **Trace (After SNOW)**
- Logs the response (success or error) returned from ServiceNow

### 🔹 **HTTP Reply**
- Sends the final response back to the original HTTP caller (e.g., Postman)

---

## ⚠️ What Happens When There's an Error (500)

1. ServiceNow responds with an error (500)
2. The **Try path breaks** and jumps to the **Catch path**
3. The **Trace in the Catch path** logs the exception details:
   ```text
   ${ExceptionList}
   ```
4. Then, the **HTTP Reply in Catch** sends a controlled error response back

---

## 🔗 Ports/Connections Clarified

- All nodes in ACE have:
  - **In terminal** (input)
  - **Out terminal** (success path)
  - **Failure terminal** (used inside Try block)
- The **Catch terminal** is **automatically triggered** if an exception occurs
- In the diagram:
  - Arrows show flow direction
  - Try and Catch are part of the **same TryCatch node**, with their own separate paths
