# **HACK-003-02-P10 — Architecture & Interface Specification (Build-Ready)**

**Status:** OPEN

## 1) Architecture Style (Selected + Justified)

### **Selected:** **Service-separated “modular monolith” (single backend deploy) + externalized async workers**
**Why this is the credible middle-ground:**
- **Not a toy:** clear bounded contexts + queues + audit plane.
- **Hackathon-realistic:** one deployable backend, but with **clean seams** for later split.
- **Compliance-ready:** audit/event ledger is first-class, not an afterthought.

**Bounded modules inside backend:**
1) Identity & Tenant  
2) Employer/HR Ops  
3) Worker Profile & Documents  
4) Visa/Status & Policy Rules  
5) Verification & Evidence  
6) Notifications  
7) Audit / Decision Trace  
8) AI Orchestration (strictly bounded)

---

## 2) Final Technology Stack (Build-Ready)

### Frontend
- **Next.js (React)**
- Auth session handling + RBAC-aware routing
- Upload UI (pre-signed URLs)

### Backend
- **Node.js + NestJS** (or Fastify-based Nest)  
- REST (primary) + optional Webhooks
- Validation: OpenAPI/Swagger generation from DTOs

### Database(s)
- **PostgreSQL** (system of record)
- **Redis** (rate limiting, ephemeral sessions, job locks, caching)

### Object Storage (documents/evidence)
- **S3-compatible** (AWS S3 / Cloudflare R2 / Supabase Storage)  
- Store **files** in object storage, store **hash+metadata** in Postgres

### Async / Background
- **Queue + worker** (BullMQ/Redis)  
- Scheduled jobs via worker (cron-like)

### AI Runtime / Model Usage (bounded)
- AI calls go through **AI Orchestrator** service
- Persist: prompt template ID, input references, output, model metadata, latency, cost estimate (if available), and **decision trace link**
- AI is **assistive + explainable**: outputs never silently mutate compliance state without a recorded rule path + human action or explicit policy automation.

### Observability
- Structured logs (JSON), request IDs, tenant IDs
- Metrics (latency, error rate, queue depth)
- Audit ledger is **separate from logs** (immutable append-only records)

---

```
   |                           |--> notification fanout
   |                           |--> periodic re-verification
   v
[Audit Ledger + Decision Trace] (Postgres tables, append-only)

External Integrations (optional, bounded):
- Email/SMS/WhatsApp provider
- eSign / verification provider
- Government/reference datasets (if allowed)
```

## 4) Authentication & Role Model (RBAC)

### Tenancy model
- **Tenant = Employer organization**
- Workers can exist:
  - **invited under a tenant**, or
  - **self-owned profile** linked to multiple tenants (if allowed by P01; otherwise tenant-scoped only)

### Roles (minimum)
1) **Employer/HR**
   - Create jobs/cases, request documents, view status, take actions
2) **Worker**
   - Manage profile, upload docs, consent, view requests, receive alerts
3) **Admin/Compliance**
   - Configure policies, approve exceptions, audit exports, lock records
4) **IT/Finance**
   - Billing/usage, integration keys, retention settings (no access to sensitive doc content by default)

### Permission approach
- **RBAC + resource scoping**
- Every request enforces:
  - tenant_id match
  - role permission
  - record-level constraints (e.g., HR can view worker only if linked)

## 7) Async Jobs & Schedulers (Canonical Set)

1) **Expiry Watcher**
   - scans documents/status nearing expiry
   - schedules notifications and/or opens CaseTask
2) **Drift Monitor**
   - detects policy/ruleset updates vs last evaluation
   - re-evaluates impacted workers/cases
3) **Evidence Completeness Checker**
   - ensures required evidence set exists per case type
4) **Notification Fanout**
   - retries, dedupe, channel fallback
5) **Audit Export Generator**
   - prepares export package for compliance/admin
6) **AI Cost/Usage Aggregator**
   - aggregates AICallLog per tenant for Finance view

- **trace_id**

### Logs/metrics (operational)
- Separate from audit
- include tenant_id + request_id for correlation
