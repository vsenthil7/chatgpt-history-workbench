---

## 1️⃣ Compliance Rule Canon (Non-Negotiable)

All decisions in VisaVerse **MUST** be produced through deterministic rule evaluation.  
AI **never creates legality**; it only **interprets inputs under locked rules**.

### 1.1 Rule Categories (Locked)

1. **Jurisdiction Rules**
   - Country / region
   - Bilateral agreements
   - Local labour law applicability
   - Data residency constraints

2. **Visa & Immigration Rules**
   - Visa type eligibility
   - Duration limits
   - Renewal constraints
   - Dependency conditions (spouse, child)

3. **Employment Authorization Rules**
   - Right-to-work validation
   - Employer sponsorship requirements
   - Role restrictions
   - Industry-specific constraints

4. **Temporal Rules**
   - Valid-from / valid-to
   - Grace periods
   - Cooling-off periods

5. **Override & Exception Rules**
   - Explicitly enumerated
   - Human-only authority
   - Logged with justification

**Rule:**  
If a condition is not explicitly encoded here, it **does not exist**.

---

## 2️⃣ Rule Evaluation Order & Precedence (Locked)

Evaluation is **strictly linear**. No branching without trace.

**Order of Execution:**

1. Jurisdiction Rules  
2. Visa & Immigration Rules  
3. Employment Authorization Rules  
4. Temporal Rules  
5. Exception / Override (if applicable)

**Precedence Law:**

- Higher order failure **halts evaluation**
- Later rules **cannot override earlier failures**
- Exceptions cannot bypass Jurisdiction Rules

**Invalid:**  
“AI inferred allowance despite rule failure”

---

## 3️⃣ Authority Boundary Matrix (Immutable)

| Actor | Authority | Can Decide? | Can Override? | Logged As |
|---|---|---|---|---|
| Deterministic Rule Engine | Legal validity | YES | NO | Rule Execution |
| AI Reasoning Layer | Interpretation & explanation | NO | NO | AI-Assist Step |
| Human Operator (Authorized) | Exception approval | YES (limited) | YES (explicit) | Human Action |
| System | Enforcement | YES | NO | System Action |

**Hard Rule:**  
AI **never** issues final legal decisions.

---

## 4️⃣ Decision Trace Schema (Canonical)

Every decision produces **exactly one immutable trace**.

### 4.1 Trace Components (Mandatory)

1. **Decision Metadata**
   - Decision ID
   - Timestamp (UTC)
   - Jurisdiction(s)
   - Actor initiating decision

2. **Rule Execution Log**
   - Rule ID
   - Rule version
   - Input parameters
   - Pass / Fail
   - Deterministic output

3. **AI-Assisted Steps**
   - Prompt reference (hash)
   - Model identifier
   - Output summary
   - Confidence level
   - Explicit disclaimer: *Non-authoritative*

4. **Human Actions (if any)**
   - Actor ID
   - Authority level
   - Justification text
   - Supporting documents

5. **Final Decision**
   - Outcome
   - Legal basis references
   - Authority source

---

## 5️⃣ Immutability & Retention Rules

### 5.1 Immutability

- Decision traces are **append-only**
- No deletion
- No overwrite
- Corrections require **new trace referencing old trace**

### 5.2 Retention

- Minimum: **7 years**
- Jurisdiction-specific extensions supported
- AI prompts & outputs retained as hashes + summaries

---

## 6️⃣ Audit Export Guarantees (Locked)

System **MUST** support regulator-grade export with:

- Who decided
- What rules fired
- When each step occurred
- Why the decision was allowed or denied
- What AI contributed (clearly labeled)
- What humans approved (if applicable)

**Export formats:**  
PDF / CSV / JSON (structure fixed)

---

## 7️⃣ Invalid Decision Conditions (Hard Fail)

A decision is **INVALID** if:

- No deterministic rule path exists
- AI output is treated as authority
- Human override lacks explicit justification
- Trace is incomplete
- Rule version is missing

Invalid decisions **must be rejected**, not corrected silently.

---

## 🔒 FINAL CANON RULE

> **No trace → No decision**  
> **No rule → No legality**  
> **No authority → No override**
