## 02_ARCHITECTURE_DESIGN — Core Task Execution

image_group{"query":["Atlassian Forge app architecture diagram","Jira Cloud Forge app data flow","Atlassian Rovo agent workflow diagram"]}

---

### A) **System Context (Boundary Definition)**

**Host Platforms**
- **entity["company","Atlassian Forge","serverless app platform"]** — serverless runtime, auth, permissions, app lifecycle.
- **entity["company","Jira Cloud","issue tracking saas"]** — primary data source and sink (issues, fields, comments).
- **entity["company","Atlassian Rovo","enterprise ai agents"]** — sole AI engine for inference, reasoning, and recommendations.

**Product Boundary**
- Jira Risk Sentinel is a **Forge app** that **invokes a Rovo Agent** to assess risk signals on Jira issues and **writes structured outputs back to Jira**.  
- No external AI, no external storage, no non-Forge compute.

---

### B) **Forge App Structure (Modules & Responsibilities)**

**1) UI Modules**
- **Issue Panel (Read/Action)**
  - Displays current risk status, last assessment timestamp, confidence score.
  - Provides explicit “Run Risk Assessment” action.
- **Admin Page**
  - Toggle scopes (project-level enablement).
  - Select trigger modes (manual, workflow-triggered).
  - View audit summaries (counts, last run).

**2) Backend Functions**
- **Risk Orchestrator**
  - Validates permissions & scopes.
  - Collects Jira context payload.
  - Calls Rovo Agent with contract-bound prompt.
- **Result Applier**
  - Parses Rovo output (strict schema).
  - Writes results to Jira (fields, labels, comments).
- **Audit Logger**
  - Emits Forge logs (no PII persistence).

**3) Triggers**
- **Manual**: Issue panel action.
- **Workflow**: Jira Automation → Forge function (optional but defined).
- **Scheduled**: Not enabled by default (defined, off).

---

### C) **Rovo Agent Architecture**

**Agent Name:** `RiskSentinel-Agent`

**Capabilities**
- Contextual reasoning over issue metadata.
- Pattern detection (risk indicators).
- Deterministic, schema-bound output.

**Inputs (from Forge)**
```text
{
  issue: {
    id, key, type, priority, status,
    summary, description,
    reporter, assignee,
    labels, components,
    created, updated,
    comments[], changelog[]
  },
  project: { key, name },
  org_context: { instance_id }
}
```

**Outputs (to Forge)**
```text
{
  risk_level: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL",
  confidence: 0.00–1.00,
  signals: [
    { type, evidence, severity }
  ],
  recommendation: {
    summary,
    suggested_actions[]
  }
}
```

**Guardrails**
- No hallucinated fields.
- No external assumptions.
- If insufficient data → `risk_level = "UNKNOWN"` with rationale.

---

### D) **End-to-End Data Flow**

1. **Trigger**
   - User clicks “Run Risk Assessment” *or* workflow fires.
2. **Forge Context Assembly**
   - Forge fetches issue + related metadata via Jira APIs.
3. **Rovo Invocation**
   - Forge sends context + fixed prompt to `RiskSentinel-Agent`.
4. **AI Evaluation**
   - Rovo reasons strictly within provided context.
5. **Structured Response**
   - JSON schema returned to Forge.
6. **Jira Write-back**
   - Custom field update (risk_level, confidence).
   - Comment added (signals + recommendation).
   - Optional label/tag applied.
7. **Audit Log**
   - Execution metadata logged (Forge logs only).

---

### E) **Prompt Contract (Fixed, Non-Mutable)**

**System Instruction (Immutable)**
> You are an enterprise risk analysis agent operating only on provided Jira issue data. Do not infer beyond evidence. Respond strictly in the output schema.

**User Instruction (Generated by Forge)**
> Assess delivery and operational risk for the following Jira issue context. Identify concrete risk signals, assign a risk level, and propose mitigations.

**Constraints**
- No creativity.
- No conversational text.
- Schema-only response.

---

### F) **Permissions & Security Model**

**Scopes**
- Read: issues, comments, changelog.
- Write: issue fields, comments, labels.
- Admin: project configuration (admin page only).

**Security**
- Forge-managed auth.
- No data egress outside Atlassian.
- No long-term storage.

---

### G) **Deployment & Runtime Model**

- **Installation**: Admin installs via Atlassian Marketplace / developer install.
- **Runtime**: Event-driven Forge functions.
- **AI Runtime**: Rovo-managed inference (Atlassian-controlled).
- **Scaling**: Automatic via Forge.
- **Failure Handling**:
  - Rovo timeout → safe failure comment.
  - Schema violation → no write-back, log only.

---

### H) **Component-Level Summary**

| Component | Responsibility | Owner |
|---------|----------------|-------|
| Issue Panel | User interaction | Forge UI |
| Risk Orchestrator | Flow control | Forge Fn |
| Rovo Agent | Risk reasoning | Rovo |
| Result Applier | Jira updates | Forge Fn |
| Audit Logger | Traceability | Forge |

---

### I) **Architecture Closure Criteria**

- All components defined ✔
- AI interaction contract fixed ✔
- Data flow deterministic ✔
- No scope drift ✔
