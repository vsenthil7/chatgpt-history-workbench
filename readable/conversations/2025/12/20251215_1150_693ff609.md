### Objective (tight restatement)
Evaluate whether *any* monetisation paths are **realistically feasible** with the current toolchain  
(**ChatGPT, Google AI Pro, NotebookLM + human execution**), without building, selling, or committing.

This page produces **decisions**, not artifacts.

---

## What “Monetisable” Means *Here*
A candidate is considered monetisable **only if** all are true:
1) Can be delivered reliably with current tools + human effort  
2) Has a plausible buyer and payment path  
3) Does not require unsupported ops (hosting, billing, auth, scale)  
4) Can be repeated without fragile manual heroics

If any fail → **NO** or **NOT NOW**.

---

## Evaluation Grid (used for every idea)

For each idea, we will record:

**A. Output Type**
- Text / Analysis / Report
- Files (PDF, XLSX, ZIP)
- Automation / Script
- Ongoing service / subscription

**B. Tool Fit**
- ChatGPT: enables / limits
- Google AI Pro: enables / limits
- NotebookLM: enables / limits
- Human execution: acceptable / excessive

**C. Monetisation Path**
- One-off paid deliverable
- Freemium → paid upgrade
- Pilot / custom engagement
- Subscription (flagged high-risk)

**D. Execution Gaps**
- File generation & delivery
- Payments & invoicing
- Versioning / updates
- Support & refunds
- Scale & repeatability

**E. Decision**
- **YES** — feasible now
- **NO** — structurally blocked
- **NOT NOW** — concept ok, toolchain not ready

---

## Hard Constraints (non-negotiable)
- No external infra assumed (no Stripe, no SaaS backend, no auth)
- No “future tooling” promises
- No pricing theory without delivery proof
- If it relies on automation beyond file output → default **NOT NOW**

---

## Explicit Anti-Goals
We will **reject**:
- Ideas that sound impressive but can’t be delivered cleanly
- Anything requiring continuous uptime or real-time systems
- “Just package it later” assumptions
- Monetisation that depends on virality or hype

- **NOT NOW** list with the *blocking reason*
