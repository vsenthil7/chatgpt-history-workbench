## Step-by-step profit calculator (UK FBA) — you can do this in Excel

### Inputs (per unit)
1) **Selling price (incl VAT)** = `P_vat`  
2) **VAT rate** (often 20%) = `v`  
3) **Product cost (COGS)** = `COGS` (what you pay supplier per unit)

6) **FBA fulfilment fee (per unit)** = `FBA` (depends on size/weight) citeturn2view2  
7) **Storage cost (per unit per month)** = `Stor` (estimate)  
8) **Ad cost per sale** = `Ads` (your PPC spend divided by units sold)  
9) **Return/refund allowance per unit** = `Ret` (a buffer)

### Calculations
**A) Convert price to ex-VAT**
- `P_exvat = P_vat / (1+v)`

**B) Referral fee (approx)**
- Referral fees are calculated on total sales price basis (Amazon’s description includes sales price elements). For a simple estimate:  
- `RefFee = r * P_exvat`  *(use ex-VAT for cleaner unit economics)*

**C) Total cost per unit**
- `TotalCost = COGS + InShip + FBA + Stor + Ads + Ret + RefFee`

**D) Profit per unit (ex-VAT)**
- `Profit = P_exvat - TotalCost`

**E) Profit margin**
- `Margin = Profit / P_exvat`

### Quick “is this viable?” rule of thumb
Aim for **≥ 20–30% margin** *before* you scale ads hard, because reality will compress margins.

## 5) Execution flow (the “deterministic spine”)

### Step A — Create PaymentRequest

Approvers sign with:

### Step D — Execute (idempotent)

- store external reference
- handle retries safely (exactly-once semantics at kernel level)

### Step E — Reconcile
- ingest bank statement / payout webhook
- match by reference, amount, date, payee
- produce reconciliation status
- open exception case if mismatch

### Step F — Close
- mark PaymentRequest complete
- finalize ledger entries
- lock the evidence pack (audit bundle)

This is the heart. Everything else is optional.
