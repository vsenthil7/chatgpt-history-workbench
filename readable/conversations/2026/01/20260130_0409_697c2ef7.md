# 1) Data Model Overview

EACP has 6 core domains:

1. **Identity & Ownership** (who is the agent, who owns it)
2. **Policy & Enforcement** (what is allowed, under which conditions)
3. **Execution & Tool Calls** (what happened, step-by-step)
4. **Audit Ledger** (immutable evidence, regulator-friendly)
5. **Risk & Controls** (anomaly, drift, throttles, kill-switch)
6. **Artifacts & Versioning** (agent versions, policy hashes, prompt/tool bundles)

The model is built so that:
- **Deterministic truth** sits in Registry + Audit Ledger
- **AI reasoning** influences *decisions*, but never corrupts the truth layer

# 2) Canonical Entity Schema (Logical)

## A) Agent
**Agent** is a *governed software actor* with immutable identity.

Key invariants:
- Every agent has: `agent_id`, `owner_id`, `purpose`, `risk_tier`
- Every agent version is immutable after approval

## B) Agent Version (immutable)
- Contains the *exact* bundle used in execution: prompts, tools allowed, model config, code hash, policy hash.
- You can always reconstruct “what was running”.

## C) Policy Set + Policy Rules
- Policies are versioned, hash-addressed.
- Policies include:
  - deterministic rules (deny/allow)
  - AI-interpreted clauses (ambiguity handling)
  - required approvals (human gate)

## D) Execution Run + Steps
- Every “run” is a trace with step events:
  - context snapshot
  - decision summary
  - tool requests
  - tool results
  - outcomes

## E) Audit Event (WORM)
- Append-only, immutable.
- Includes **evidence pointers** and **reason codes**.

## F) Risk Signal + Risk Decision
- Risk signals from observability + behavior analysis.
- Risk decisions trigger: throttle, quarantine, require approval, kill.

# 4) Contracts (APIs)

These are the **must-have service contracts**.

## 4.1 Agent Registry API (Deterministic)
- `POST /agents` → create agent (DRAFT)
- `POST /agents/{id}/versions` → create version bundle
- `POST /agents/{id}/versions/{v}/approve` → human approval required (or delegated policy)
- `PATCH /agents/{id}/status` → suspend/retire/quarantine
- `GET /agents/{id}` / `GET /agents?owner_id=...`

**AI%:** 0% (strict)

---

## 4.2 Policy Decision API (Hybrid)
- `POST /policy/evaluate`
Input:
- agent identity + version hash bundle
- requested tool/action/resource
- context claims (ABAC): env, incident severity, business unit, data class

Output:
- decision: ALLOW/DENY/REQUIRE_APPROVAL
- reason_code
- (optional) AI interpretation trace + confidence

**AI%:** 60% inside “ambiguity clause interpretation”, but decision gating remains deterministic:
- deterministic rules first
- AI only fills ambiguity gap
- fallback to DENY/APPROVAL if confidence low

---

## 4.3 Execution Orchestrator API
- `POST /runs` start run
- `POST /runs/{id}/steps` append step
- `POST /runs/{id}/tool-call` request tool execution (enforced through policy)
- `POST /runs/{id}/close` final state

**AI%:** 70% in planning/step selection, 0% in logging truth.

---

## 4.4 Audit API (Append-only)
- `POST /audit/events` (append-only)
- `GET /audit/search?subject_id=...`
- `GET /audit/runs/{run_id}/timeline`

**AI%:** 0%
