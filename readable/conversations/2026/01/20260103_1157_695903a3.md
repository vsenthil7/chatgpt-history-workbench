# 1) The “Do NOT copy” doctrine — step-by-step (locked)

## 1.1 Do NOT copy “App-store chaos”
**When you open third-party apps too early, you accidentally create a second company inside your company: platform governance.**

**Why it fails early (step-by-step):**
1. You must build **permissions** (what app can read/write).
2. You must build **review/approval** (malware/fraud risk).
3. You must build **billing + rev-share + refunds** for apps.
4. Support becomes combinatorial: “Theme A + Plugin B + Android C”.
5. Security incident hits brand: shopkeeper blames **you**, not plugin author.

**Enterprise rule:**  
✅ Early: **first-party modules only**  
✅ Later: curated partner integrations (not open marketplace)  
✅ Much later: real app store (if ever)

---

## 1.2 Do NOT do “Early plugin explosion”
**Plugins freeze your architecture before you understand your primitives.**

Step-by-step:
1. Early you keep changing “Product/Order/Inventory” contracts.
2. Plugins depend on those contracts → every change breaks partners.
3. You stop refactoring → debt becomes permanent.
4. Product learning slows (edge cases dominate).

**Enterprise rule:**  
Open extension points only after: **stable primitives + stable APIs + stable uptime + stable support**

---

## 1.3 Do NOT allow “Over-customisation too early”
Infinite knobs create infinite support states.

Step-by-step:
1. Bugs become configuration-specific.
2. Onboarding becomes impossible (“every shop behaves differently”).
3. Testing matrix explodes.
4. Support cost destroys margins.

**Enterprise rule:**  
Start with **opinionated defaults** + **small safe configuration**, then progressively disclose more knobs.

---

## 1.4 Don’t build “Apex-level programmability” early (even with AI code builder)
AI can generate code; the hard part is **safe execution inside a multi-tenant SaaS**.

Step-by-step:
1. You need a **sandbox runtime** (prevent infinite loops / runaway costs).
2. You need **tenant isolation** at runtime (no data leakage).
3. You need **permissioning** (what code can modify).
4. You need **auditability** (who changed price/refund/stock).
5. You need **versioning & rollback** (platform upgrades break scripts).
6. You become a “developer platform” + “support desk for custom code”.

**Enterprise rule (the safe ladder):**
- Level 1: Config toggles  
- Level 2: Rules engine (constrained DSL, no arbitrary code)  
- Level 3: AI suggests rules (human approves)  
- Level 4: Constrained actions (serverless-like, but only preapproved ops)  
- Level 5: Programmability (only if platform matures + strict governance)
