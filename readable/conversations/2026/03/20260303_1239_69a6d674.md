# 2️⃣ What is BigQuery?

BigQuery is:

> A **serverless analytical data warehouse**.

It is built for:
- Massive analytics
- OLAP workloads
- Scanning terabytes/petabytes
- Reporting / dashboards / BI
- ML over structured data

Not built for:
- High-frequency transactions
- Row-level real-time updates

### A) What lives in Spanner
Put **current state** + **transactional integrity** here:

### B) What lives in BigQuery
Put **history + aggregation + analytics** here:
- Event history / change history

### Pattern 1 — Near real-time analytics (recommended)
**CDC from Spanner → streaming pipeline → BigQuery**
- Low latency (seconds–minutes)

- Best for monitoring, fraud signals, operational dashboards

### Pattern 2 — Batch analytics
**Scheduled export / batch ETL → BigQuery**
- Lower cost, simpler ops
- Good when near-real-time isn’t required

### Spanner schema
- Normalize for correctness and transactional safety
- Use primary keys designed for write distribution (avoid hotspots)
- Keep secondary indexes purposeful (OLTP performance)

### BigQuery model
Use a warehouse model (often **star schema**):
- **Facts:** transactions, events, payments, claims
- **Dimensions:** customer, product, geography, time
- Partition by event/transaction date
- Cluster by high-cardinality filters (customer_id, account_id)

  - compliance packs

- operational integrity (Spanner)
