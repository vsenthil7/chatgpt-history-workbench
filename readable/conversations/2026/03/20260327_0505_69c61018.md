# Step 1 — What the scheduler does

In this stack, **Airflow** is the scheduler/orchestrator of the data pipeline itself. Airflow documentation says the scheduler monitors DAGs and triggers task instances once dependencies are complete. It also supports event-driven scheduling in newer versions, so a workflow can run because of time or because an external event arrives. citeturn823958search3turn823958search17turn823958search20

## Practical Airflow role

At **07:00 every day**, Airflow runs a DAG like:

```text
sales_pipeline_monitor
```

That DAG may do three things:

1. Check whether ingestion finished
2. Check whether dbt freshness/tests look healthy
3. Trigger an AI-based incident-investigation step only if something is wrong

At this point, Airflow is **not the AI agent**. It is just the **time/event trigger plus workflow runner**. That’s the key difference. citeturn823958search3turn823958search17

---

# Step 2 — What the AI agent does

Now the Airflow DAG calls an **agent service** built with the OpenAI Responses API or the OpenAI Agents SDK. OpenAI’s docs describe the Responses API as a unified way to build agent-like apps with built-in tools and remote MCPs, and the Agents SDK as a way to build agentic apps with tools, handoffs, and full traces. citeturn823958search21turn823958search1

## Practical agent goal

Airflow passes a goal such as:

```json
{
  "pipeline": "sales_daily",
  "business_date": "2026-03-26",
  "trigger_reason": "freshness_failed"
}
```

The **AI agent** then owns the task:

- investigate what failed
- gather evidence
- classify severity
- notify the right people
- create a Jira incident if needed

So here:

- **Airflow** = starts the work
- **AI agent** = manages the investigation workflow

That is a real separation of responsibilities, not theory. citeturn823958search3turn823958search1turn823958search11

# Step 3 — Where the LLM fits

Inside that agent, the **LLM** is the reasoning engine.

OpenAI’s tool docs describe tools and remote MCPs as extensions to the model’s capabilities, while the Responses API supports multi-turn reasoning and tool use. In practice, that means the model can inspect evidence, decide what to check next, and turn technical details into a readable explanation. citeturn823958search4turn823958search21turn823958search0

## Example

Suppose the agent receives this raw signal:

```text
dbt source freshness failed for source: sales_orders
max_loaded_at = 2026-03-26 03:05:00
error_after = 2 hours
current_time = 2026-03-26 07:00:00
```

dbt’s source freshness feature is specifically meant to measure how recent the newest record is, compared with now, and it supports warning/error thresholds. citeturn393022search4turn393022search0

The LLM can turn that into:

> “The source appears stale by nearly two hours beyond the configured threshold, so downstream models may produce incomplete sales reporting.”

That interpretation layer is what the LLM adds. The scheduler does not do this. The protocol does not do this. The warehouse does not do this. citeturn393022search4turn823958search21

So the agent does **not** hardcode 20 different custom integrations into the prompt. Instead, it asks for tools through MCP. That is the practical value of MCP. citeturn823958search14turn823958search22turn823958search16

# Full Python script

```python
import os
import json
import smtplib
from pathlib import Path
from datetime import datetime, timezone
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart
from typing import Any, Dict, List

from openai import OpenAI


# =========================
# CONFIG
# =========================

OPENAI_TEXT_MODEL = "gpt-5.4"
OPENAI_TRANSCRIBE_MODEL = "gpt-4o-mini-transcribe"

AUDIO_FILE = "meeting.m4a"  # change to your file

OUTPUT_DIR = Path("output")
OUTPUT_DIR.mkdir(exist_ok=True)

# Email notification config
SMTP_HOST = "smtp.gmail.com"
SMTP_PORT = 587
SMTP_USERNAME = os.getenv("SMTP_USERNAME", "")
SMTP_PASSWORD = os.getenv("SMTP_PASSWORD", "")
EMAIL_FROM = os.getenv("EMAIL_FROM", "")
EMAIL_TO = os.getenv("EMAIL_TO", "")

client = OpenAI()


# =========================
# STEP 1: TRANSCRIBE AUDIO
# =========================

def transcribe_audio(audio_path: str) -> str:
    """
    Transcribe an audio file using OpenAI's transcription API.
    """
    with open(audio_path, "rb") as f:
        transcript = client.audio.transcriptions.create(
            model=OPENAI_TRANSCRIBE_MODEL,
            file=f,
        )

    # Depending on SDK response shape, text is usually available here.
    # Keep this tolerant in case the SDK object changes shape slightly.
    text = getattr(transcript, "text", None)
    if not text:
        raise RuntimeError("Transcription returned no text.")
    return text


# =========================================
# STEP 2: SUMMARIZE + EXTRACT TASKS IN JSON
# =========================================

def analyze_transcript(transcript_text: str) -> Dict[str, Any]:
    """
    Ask the model for a summary + action items in strict JSON format.
    """
    prompt = f"""
You are an operations analyst.

Read the transcript below and return ONLY valid JSON with this exact shape:

{{
  "title": "short title",
  "summary": "3-8 sentence summary",
  "participants": ["name1", "name2"],
  "key_points": ["point 1", "point 2"],
  "action_items": [
    {{
      "task": "what needs to be done",
      "owner": "person name or Unknown",
      "due_date": "ISO date if explicit, else null",
      "priority": "high|medium|low",
      "status": "open"
    }}
  ],
  "risks": ["risk 1", "risk 2"],
  "follow_ups_needed": true
}}

Rules:
- Return JSON only. No markdown.
- If owner is unclear, use "Unknown".
- If due date is unclear, use null.
- Do not invent facts not present in the transcript.
- If there are no action items, return an empty list.

Transcript:
\"\"\"
{transcript_text}
\"\"\"
"""

    response = client.responses.create(
        model=OPENAI_TEXT_MODEL,
        input=prompt,
    )

    raw = response.output_text.strip()

    try:
        return json.loads(raw)
    except json.JSONDecodeError as e:
        # Save the raw response for debugging
        debug_file = OUTPUT_DIR / "bad_model_output.txt"
        debug_file.write_text(raw, encoding="utf-8")
        raise RuntimeError(
            f"Model output was not valid JSON. Saved raw output to {debug_file}"
        ) from e


# =========================
# STEP 3: STORE RESULTS
# =========================

def store_results(audio_path: str, transcript_text: str, analysis: Dict[str, Any]) -> Path:
    """
    Save everything into one JSON file.
    """
    timestamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
    stem = Path(audio_path).stem

    payload = {
        "created_at_utc": timestamp,
        "source_audio_file": audio_path,
        "transcript": transcript_text,
        "analysis": analysis,
    }

    output_file = OUTPUT_DIR / f"{stem}_{timestamp}.json"
    output_file.write_text(json.dumps(payload, indent=2, ensure_ascii=False), encoding="utf-8")
    return output_file


# =========================
# STEP 4: EMAIL NOTIFY
# =========================

def send_email_notification(result_file: Path, analysis: Dict[str, Any]) -> None:
    """
    Send a simple email summary.
    """
    if not all([SMTP_USERNAME, SMTP_PASSWORD, EMAIL_FROM, EMAIL_TO]):
        print("Email config not set. Skipping notification.")
        return

    subject = f"[Transcript Processed] {analysis.get('title', 'Untitled')}"
    summary = analysis.get("summary", "")
    action_items: List[Dict[str, Any]] = analysis.get("action_items", [])

    lines = [
        f"Result file: {result_file}",
        "",
        "Summary:",
        summary,
        "",
        "Action Items:",
    ]

    if action_items:
        for idx, item in enumerate(action_items, start=1):
            lines.append(
                f"{idx}. Task: {item.get('task')} | "
                f"Owner: {item.get('owner')} | "
                f"Due: {item.get('due_date')} | "
                f"Priority: {item.get('priority')}"
            )
    else:
        lines.append("No action items found.")

    body = "\n".join(lines)

    msg = MIMEMultipart()
    msg["From"] = EMAIL_FROM
    msg["To"] = EMAIL_TO
    msg["Subject"] = subject
    msg.attach(MIMEText(body, "plain", "utf-8"))

    with smtplib.SMTP(SMTP_HOST, SMTP_PORT) as server:
        server.starttls()
        server.login(SMTP_USERNAME, SMTP_PASSWORD)
        server.sendmail(EMAIL_FROM, [EMAIL_TO], msg.as_string())

    print(f"Notification sent to {EMAIL_TO}")


# =========================
# MAIN
# =========================

def main() -> None:
    print(f"Transcribing: {AUDIO_FILE}")
    transcript_text = transcribe_audio(AUDIO_FILE)

    transcript_file = OUTPUT_DIR / "transcript.txt"
    transcript_file.write_text(transcript_text, encoding="utf-8")
    print(f"Transcript saved to {transcript_file}")

    print("Analyzing transcript...")
    analysis = analyze_transcript(transcript_text)

    result_file = store_results(AUDIO_FILE, transcript_text, analysis)
    print(f"Structured result saved to {result_file}")

    send_email_notification(result_file, analysis)

    print("\nDone.")
    print(json.dumps(analysis, indent=2, ensure_ascii=False))


if __name__ == "__main__":
    main()
```

# How the flow works

## 1. `client.audio.transcriptions.create(...)`
This sends the audio file to the transcription endpoint. OpenAI’s speech-to-text docs list supported input formats including `mp3`, `mp4`, `m4a`, `wav`, and `webm`, and note a current file upload limit of 25 MB for standard transcription requests. citeturn993475search0turn993475search8

## 2. `client.responses.create(...)`
This sends the transcript text to the Responses API for summarization and task extraction. OpenAI currently recommends the Responses API for new projects and positions it as the main text-generation interface for agent-like applications. citeturn113319search4turn113319search8turn113319search1

## 3. JSON store
This example stores results locally in a JSON file. In a real product, you would usually swap this with:
- PostgreSQL
- Google Sheets
- Airtable
- Notion
- internal task database

## 4. notify
This example uses SMTP email only because it is easy to understand. In a product, this could instead be:
- Slack webhook
- Teams message
- WhatsApp provider
- task-system update
