# What Claude's features actually mean for us

The useful way to understand Claude is **not as one AI chat window**. It is increasingly a stack:

**Model → effort/reasoning → planning → Skills → subagents → tools/MCP → automation → Git → verification**

That is extremely relevant to what we have been building.

## 1. Model + effort = choose how much intelligence to spend

Anthropic now supports different Claude models and increasingly explicit control over how much effort Claude puts into a task. Their newer Opus releases also support faster execution options and larger agentic workflows. citeturn0search0turn0search5

For us, don't use maximum intelligence for everything.

| Our work | Suggested approach |
|---|---|
| Rename/format/extract data | Fast/cheap |
| Transcript classification | Fast/cheap |
| KB entry generation | Normal |
| Research | Normal/high |
| Architecture | High |
| Difficult debugging | High |
| Postmortem | High |
| Protocol changes | High |
| Final independent review | High/separate agent |

### Benefit

This addresses one of the problems we've already discussed: **why spend expensive reasoning tokens on mechanical work?**

Our future router should decide:

> **Task → complexity → model → effort → tools → reviewer**

rather than sending everything to the most expensive Claude.

---

# 2. Skills — this may be one of the most valuable Claude features for us

Anthropic's **Skills** are reusable folders containing instructions, scripts and resources. Claude loads a Skill when the current task requires it rather than stuffing all of those instructions into every prompt. Skills can also be combined and reused across Claude apps, Claude Code and the API. citeturn0search1

This maps almost perfectly to what you've been trying to create.

Instead of repeatedly telling Claude:

> Don't forget Git Turn.  
> Preserve raw evidence.  
> Don't overwrite.  
> Update timeline.  
> Check usage.  
> Do postmortem.  
> Verify sources...

we should eventually package these behaviours.

For example:

```text
skills/
    git-turn/
    transcript-ingest/
    evidence-preservation/
    source-verification/
    postmortem/
    kb-builder/
    kb-reviewer/
    usage-recorder/
    next-page-handover/
```

Then you say:

> Analyse this call and postmortem it.

Claude can invoke the relevant Skills rather than requiring you to repeat 30 instructions.

### Benefit for you

This attacks something that has been irritating you repeatedly:

**"Why do I have to remind the AI again about Git?"**

The long-term answer shouldn't be **better reminders from you**.

It should be:

> **Encode the behaviour once.**

# 3. Subagents — Claude can create specialist workers

Anthropic's current guidance explicitly discusses Claude orchestrating **subagents**. It also warns that agents shouldn't be spawned unnecessarily; simple tasks are often better done directly. citeturn1search0

We already have the beginning of this idea in `_kb`: T023 created **KB Builder + KB Reviewer** agents.

Our mature version could look like:

```text
                    ORCHESTRATOR
                         |
        +----------------+----------------+
        |                |                |
   Researcher         Builder         Evidence Agent
        |                |                |
        +----------------+----------------+
                         |
                      Reviewer
                         |
                    Git-TURN QA
```

For your call/transcript work, for example:

**Researcher**
→ establishes external facts.

**Transcript/Evidence agent**
→ preserves what was actually said.

**Analyst**
→ interprets it.

**Skeptic**
→ searches for alternative explanations.

**Reviewer**
→ asks whether the conclusions are actually supported.

**Git agent**
→ makes sure the entire exercise survives the chat page.

### Benefit

This is much stronger than asking the **same model to create something and then congratulate itself for creating it correctly**.

# 4. MCP / connectors — connect Claude to the actual world

MCP/connectors allow Claude to interact with external systems rather than having you manually copy information into prompts.

Potential architecture for us:

```text
Claude
   |
   +--- GitHub
   +--- Google Drive
   +--- Browser
   +--- Database
   +--- Files
   +--- APIs
   +--- Internal tools
```

Anthropic is continuing to expand connector-based workflows across its products. citeturn0search3

But I would **not** connect everything with write access.

Our rule should be:

```text
READ
  ↓
ANALYSE
  ↓
PROPOSE
  ↓
VERIFY
  ↓
WRITE
```

And start with **least privilege**.

### Benefit

You stop being the human API:

> Download this → upload here → copy that → paste there → ask Claude → copy result → upload elsewhere.

That manual glue can gradually disappear.

# 5. Hooks/scripts — extremely important for your Git problem

There are things we should **not trust an LLM to remember**.

Example:

```text
Claude finishes work
       ↓
secret scan
       ↓
protocol validator
       ↓
tests
       ↓
Git-TURN exists?
       ↓
usage exists?
       ↓
timeline updated?
       ↓
commit
       ↓
remote verification
```

Your `_kb` protocol already requires secret checking, one commit per turn, timeline tracking and remote verification. fileciteturn5file0L2-L2

The important architectural principle is:

> **LLM handles judgment. Code enforces invariants.**

So instead of hoping Claude remembers Git-TURN every time, a validator should eventually reject completion when Git-TURN is absent.

That is much stronger.

```text

   ↓

   ↓

   ↓
```

If the context dies after batch 37, the next agent reads Git and starts at **38**.

It doesn't need to "remember."

# 9. What I would build first

I **wouldn't chase every new Claude feature**.

Our order should be:

**Phase 1 — Git backbone**

Keep Git Turn v1.2 as the source-of-truth mechanism.

**Phase 2 — five core Skills**

```text
git-turn
evidence-ingest
research-verification
builder
reviewer
```

**Phase 3 — deterministic validation**

Make it mechanically difficult for Claude/ChatGPT to finish without the required Git artefacts.

**Phase 4 — intelligent routing**

```text
Task
 ↓
Simple? ──→ Direct/cheap
 ↓ no
Parallel? ─→ Subagents
 ↓
High consequence? ─→ High effort + reviewer
```

**Phase 5 — MCP/connectors**

Only add integrations that remove actual manual work.

**Phase 6 — measurement**

Track:

```text
cost
tokens
latency
retries
agent count
failures
review findings
human corrections
task success
```

Then we can answer scientifically:

> Did multi-agent Claude actually improve the outcome?

rather than assuming that more agents = better.

## What exactly is a Claude Mod?

A Claude Mod is **not another Claude model** and not simply a Skill.

Anthropic describes Mods as small TypeScript functions that can change how Claude Code itself behaves. A Mod can intercept Claude Code events before/after/instead of the normal behavior. It can rewrite prompts, block/retry tool calls, approve/deny permissions, redact tool output, create UI, add buttons and inputs, and even replace built-in Claude Code functionality. Anthropic says you can even ask Claude Code to **write a Mod for Claude Code**, install it, and hot-reload it. citeturn2view0

So conceptually:

```text
Normal plugin
    ↓
adds capabilities

Skill
    ↓
teaches Claude how to perform something

Hook
    ↓
runs when an event occurs

MOD
    ↓
can intercept + modify + replace + visualize
Claude Code's own behaviour
```

That last capability is what makes this especially interesting for us.

# And you remembered the "pages talking to each other" part too

This is where the research became particularly interesting.

There are already Mods exploring exactly that.

**Crosstalk** opens a pane containing conversations between the current Claude Code session and other Claude Code sessions and lets one session reply to another. citeturn4search1

**Session Bridge** goes even further: it is described as allowing Claude Code sessions to talk to other sessions, including **meetings between two sessions**. citeturn4search6

So there are actually **three layers** here:

| Layer | Purpose |
|---|---|
| **Agent View** | Official multi-session manager |
| **Claude Mods** | Programmable Claude Code UI/event/control system |

That combination is much closer to what you were describing.
