# 4. Official YouTube API: playlist = good, transcript = problem

## Playlist discovery — supported

The official YouTube Data API provides `playlistItems.list`.

It can retrieve the items belonging to a specified playlist, including position and video identifiers. A call costs only **1 quota unit**, and pagination is officially supported. citeturn0search1turn0search7

So L0 is comparatively straightforward:

```text
Playlist URL
     ↓
extract playlist ID
     ↓
YouTube Data API
     ↓
playlistItems.list
     ↓
Video IDs + order + metadata
```

**Classification: 🟢 Official / supported**

This should probably become our normal playlist-discovery mechanism.

# 11. Legal / platform-policy boundary

This matters before we automate unofficial retrieval at scale.

YouTube's current Terms prohibit automated access such as robots/botnets/scrapers except in specified circumstances such as prior written permission, public-search-engine access under robots.txt, or where applicable law permits it. citeturn0search10

YouTube's API terms separately require API clients to access the services through permitted documented means. citeturn1search12

```text

      ├── Licensed third party
      ├── User-provided
      └── Fallback
```

The learning system must survive even if one acquisition method disappears tomorrow.

**Advantage:** stable and compliant.

Useful for an **experiment**, but I would not make the entire learning architecture dependent on it.


**This is my recommended architecture.**
