## `AGENTS.md` should NOT contain everything

This is an important lesson from their design.

Don't make a 2,000-line monster saying everything an AI might ever need.

`AGENTS.md` becomes the **constitution**:

```text
# TalkProof Agent Constitution

1. Git is authoritative.
2. Never claim implementation without code evidence.
3. Never claim test success without executable evidence.
4. Read current tracker before changing product state.
5. Preserve traceability.
6. Every engineering turn follows git-turn.
7. Implementation and independent review remain separate.
8. Product-owner blocked decisions cannot be silently assumed.
9. Never hide failures.
10. Every completed unit leaves a reproducible handoff.
```

Then detailed procedures move into skills.

That matches OpenClaw's philosophy: skill bodies are supposed to be **operational and terse**, while reusable command logic belongs in helper scripts. citeturn0search3turn0search4

## One major warning

A skill gives the model **procedure**.

It does **not magically give every environment identical capabilities**.

For example, our skill might say:

```text
1. git status
2. read tracker
3. inspect last commit
4. perform review
5. run tests
6. create artifact
7. update tracker
8. commit artifact
```

Claude Code with repository/shell access could execute all of that.

Claude web can understand and follow the same workflow, but whether it can perform each operation depends on the tools/connectors/environment available in that Claude session.

Likewise, a ChatGPT skill doesn't magically give ChatGPT access to a Git repository. OpenAI describes the same separation: **skills provide the workflow; tools/plugins provide live information and actions.** citeturn0search9

So:

```text
SKILL = HOW I WANT THE AI TO WORK

TOOLS = WHAT THE AI IS ACTUALLY ABLE TO DO
```

That's the key distinction.
