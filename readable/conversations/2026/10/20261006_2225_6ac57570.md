## 06/10/2026 23:44 — Work/Dot vs Git Turn Protocol

**Yes, you can require Work or Dot to follow your Git turn protocol. But I would not trust either one merely because you told it once.**

There are two separate questions here:

### 1. Can it follow your protocol? **Yes.**

Your protocol can become part of the task/project instructions, for example:

> Before work → read current Git state → identify active sprint/WP → perform work → run tests → write review/audit artifact → update tracker → commit → push → report commit SHA → only then proceed to next WP.

Work supports Projects with persistent instructions/context, local folders/repos on desktop, and you can **follow progress, intervene, change direction, and approve actions**. citeturn0search3turn0search5

Dot goes further: it supports **custom rules** governing how it behaves, can use its own cloud computer, can optionally work on your local computer, and can create Work or Codex tasks. citeturn0search0turn0search1

So conceptually your **Git Turn Protocol can become a rule of operation rather than something you remind me about every turn.**

### 2. Will it expose literally everything it does? **No — and this distinction matters.**

Work is not simply a black box. OpenAI explicitly says you can **follow progress in the conversation**, review results, answer questions and redirect it while it works. Cloud-browser tasks also expose progress and confirmation requests. citeturn0search2turn0search4

Dot gives even more operational visibility: its profile has **In Progress / Scheduled / Completed**, and you can open its cloud computer and interact with it. citeturn0search0

But that does **not** mean you receive a complete internal reasoning trace of every decision. You should design your protocol around **observable evidence**, not around seeing its private reasoning.

That actually suggests a stronger version of what you've been doing with TalkProof:

**Don't ask the AI to "show me everything you're thinking." Make the repository prove everything it did.**

```text
TASK START
   ↓
Read Git HEAD
   ↓
Read Sprint / WP / Review state
   ↓
Write TURN-START checkpoint
   ↓
Perform ONE bounded unit
   ↓
Tests / evidence
   ↓
Update tracker + traceability
   ↓
Create TURN-END audit artifact
   ↓
git diff
   ↓
commit
   ↓
push
   ↓
verify remote SHA
   ↓
Only then next unit
```

Then even if Work/Dot performs 50 operations internally, **the authoritative history isn't its narration**. It is:

**Git commit + diff + test evidence + tracker + audit artifact + SHA.**

### The interesting consequence for your current process

Today, *you* are partly acting as the orchestration engine:

**Senthil → ChatGPT review → Git artifact → Claude → Claude code → Git → ChatGPT → review → tracker → next WP.**

With Work, much of that coordination could potentially become:

**You → Work → Git/Codex/other tasks → tests → evidence → Git checkpoint → you approve decision gate.**

And eventually Dot could sit one level above that:

```text
                         YOU
                          │
                    Decision gates
                          │
                          ▼
                         DOT
                  persistent coordinator
                          │
             ┌────────────┼────────────┐
             ▼            ▼            ▼
           Work         Codex       Other tools
             │            │
             └──────┬─────┘
                    ▼
               Git protocol
                    │
         ┌──────────┼──────────┐
         ▼          ▼          ▼
       Code       Tests      Reviews
         │          │          │
         └──────────┼──────────┘
                    ▼
              Evidence/commit
                    │
                    ▼
                   YOU
```

That is much closer to what I think you actually want than "AI secretly does everything."

**I would explicitly prohibit autonomous skipping of your Git protocol.** A task isn't complete because Work/Dot says *done*. It is complete only when the required Git evidence exists.

And interestingly, Dot's current design supports this philosophy: OpenAI describes it as taking ongoing responsibility but **returning to the human for decisions requiring judgment**, rather than removing the human entirely. citeturn0search0

So for your TalkProof-style work, my position is: **automate the labour and orchestration, not the audit trail or your decision gates.**

That could remove a large amount of the manual "continue → did you commit? → did you update tracker? → follow protocol → now next WP" loop you've been doing, without turning development into an invisible black box. memcite
