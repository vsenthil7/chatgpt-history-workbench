### What happens during one call

Imagine somebody calls:

> "Hi, I'd like to book an appointment for Tuesday."

The flow is approximately:

**1. Phone network**

```text
Caller
   ↓
Twilio / Retell number / SIP
   ↓
Retell
```

Retell receives the live audio stream.

**2. Real-time conversation layer**

This is one of the important things Retell is selling you rather than you building yourself.

It has to deal with:

```text
speech
   ↓
when did caller stop speaking?
   ↓
did caller interrupt the AI?
   ↓
should AI stop talking?
   ↓
background noise / silence
   ↓
conversation turn
```

This orchestration is a major difference between building a normal LLM chatbot and building a usable telephone agent.

**3. Speech understanding + LLM**

Conceptually:

```text
"Can I book Tuesday afternoon?"
             ↓
       speech recognition
             ↓
       conversation context
             ↓
             LLM
             ↓
      determine intention

Intent = BOOK_APPOINTMENT
```

The intelligence layer can use Retell's agent/LLM configuration and conversation flows, or you can integrate custom logic depending on the design.

**4. Tool/function call**

The LLM shouldn't invent appointment availability.

Instead:

```text
Retell Agent
      │
      │ tool/function call
      ▼
YOUR BACKEND
      │
      ├── Google Calendar
      ├── CRM
      ├── Database
      ├── Salesforce
      ├── HubSpot
      └── Your API
```

For example:

```text
check_availability(
    date="2026-10-06",
    period="afternoon"
)
```

Your API might return:

```text
14:00
15:30
16:30
```

Then the LLM formulates:

> "I have 2 PM, 3:30 PM and 4:30 PM available. Which works best?"

**5. Voice generation**

Conceptually:

```text
LLM text
   ↓
TTS
   ↓
streaming audio
   ↓
Retell
   ↓
Twilio/SIP
   ↓
Caller
```

The caller hears the answer while the system remains ready for interruption.

Retell's web voice mode, for example, uses real-time WebRTC audio. citeturn0search1

### The key takeaway

**Twilio = telephone/network layer.**

**Retell = real-time voice-agent runtime/orchestration layer.**

**LLM = reasoning/conversation intelligence.**

**Your backend = actual business logic and system of record.**

**CRM/Calendar/RAG/APIs = tools/data used by the agent.**

For the AI receptionist requirement from your previous page, this distinction is important because **we don't need to build the hardest low-latency audio/interrupt/turn-taking layer ourselves** if Retell is the runtime. The engineering effort shifts toward the receptionist's workflows, business integrations, reliability, multi-tenancy and provider independence. memcite
