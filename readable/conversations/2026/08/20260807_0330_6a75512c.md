

# 🔴 BLOCKER 2 — “No disk I/O in core” is false

Multiple documents say `at-ingest-core`:

> does NOT touch network, disk or clock

The V006 Development Design Document says:

> “No I/O in the core.”

The Architecture Baseline repeats:

> `at-ingest-core` must not “touch network/disk/clock”

But actual `at-ingest-core` contains:

```python
def sha256_file(path: str) -> str:
    h = hashlib.sha256()
    with open(path, "rb") as fh:
        ...
```

That is **disk I/O inside the core**.

So prose and code already disagree.

More importantly, the architecture guard called:

```text
test_deterministic_core_has_no_network_or_model_imports
```

does **not enforce “no disk or clock.”**

It only forbids:

```text
requests
httpx
urllib
socket
aiohttp
openai
anthropic
boto3
azure
random
secrets
```

It does not prohibit:

```text
open()
pathlib
os
time
datetime.now()
```

So V008 claims a stronger guarantee than the test actually provides.

### Required correction

Choose one:

**A. Pure core**

Move file hashing/file reading outside `at-ingest-core`, perhaps into ingest infrastructure.

or

**B. Permit controlled local I/O**

Rewrite the architectural rule accurately.

What cannot remain is:

```text
Documentation: No disk I/O
Code: disk I/O
Test: doesn't check disk I/O
Status: PASSING
```

> **RTM-08 — Documentation cannot claim absent code**
