# 🔴 4. Claude missed a much more serious capacity defect

Claude correctly identified the fixed 500-row limit, but missed the actual capacity-calculation flaw.

Current weekly formula is effectively:

```text
IF(Planned_Hours <= Available_Hours_Week,
   "Within capacity",
   "Over capacity")
```

That checks **each task independently**.

Example:

- Resource has 10 available hours.
- Task A = 6 hours → Within capacity
- Task B = 6 hours → Within capacity
- Task C = 6 hours → Within capacity

Workbook says all three are individually within capacity.

Actual assignment:

**18 planned hours against 10 available hours.**

That is an operationally dangerous false positive.

Therefore RPR-011 needs to require:

**aggregate resource capacity by relevant time window**, not merely `planned_hours <= available_hours` on each allocation row.

This should become a new baseline finding, not disappear as an implementation detail.

# 🟠 6. Actual_Minutes has a second defect beyond midnight

Claude found:

> End − Start becomes negative across midnight.

Correct.

But there is another more fundamental problem.

The formula is:

```text
Actual_End - Actual_Start
```

Therefore pauses and interruptions are still counted as working time.

Example:

```text
Start       09:00
Pause       10:00
Resume      11:00
End         12:00
```

Elapsed time = 3 hours.

Actual worked time = 2 hours.

The workbook has no representation from which that 2 hours can reliably be calculated.

So RPR-016 should not merely become:

> Handle cross-midnight/DST/time zones.

It needs to address **event-derived active duration**, including pause/interruption semantics.
