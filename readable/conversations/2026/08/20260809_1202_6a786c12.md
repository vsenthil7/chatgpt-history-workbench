## 09/08/2026 13:02 — Codex: Web vs App vs CLI vs VS Code

Partner, **you've spotted a real product change/confusion**. I checked OpenAI's current documentation because Codex has changed substantially.

### The important part

**Codex is no longer a normal selectable mode/page in ChatGPT Web.** OpenAI's current Help Center explicitly says:

> “Codex does not appear on web.”

and says Codex remains a **separate view in the ChatGPT desktop app**, with its history separate from normal ChatGPT history. citeturn0search3

So your mental model should now be:

| Where you use Codex | Runs where? | Has conversation/thread UI? | Appears as ChatGPT Web page? |
|---|---|---|---|
| **Codex Desktop App** | Local + cloud capabilities | ✅ Yes | ❌ No |
| **Codex CLI** | Primarily your local repo | Terminal session | ❌ No |
| **Codex VS Code extension** | Local + cloud tasks | ✅ Inside VS Code | ❌ Not normal ChatGPT Web history |
| **Codex cloud task** | OpenAI cloud container | Task/thread | ⚠️ Can be surfaced through Codex clients, but not normal ChatGPT Web pages |
| **ChatGPT Work** | Cloud on web; local access on desktop | ✅ Yes | ✅ **Yes** |

OpenAI distinguishes **Codex Local** (CLI, IDE extension, desktop workflows) from **Codex Cloud** (delegated cloud tasks). citeturn0search0

### Your specific question: “If I use CLI, will it create a page in web?”

**No — don't expect `codex` CLI sessions to create ChatGPT Web pages like this conversation.**

The CLI has its own session/history mechanism. The Codex App can pick up session history/configuration from CLI and IDE workflows, which is why the experiences can feel connected. citeturn0search6

But that does **not** mean:

`Codex CLI session → ChatGPT Web Project → Web page`

That's the distinction that matters for the way **we have been organising your projects into numbered pages**.

### Codex App is different

### And VS Code?

Your intuition is also right.

With the Codex VS Code extension, the interaction lives **inside VS Code**. It has the advantage that Codex knows the files you have open and code you've selected. It can also create/track cloud tasks and bring completed cloud work back into the IDE. citeturn0search8

So:

```text
VS CODE
Repo
 ├── code
 ├── tests
 ├── docs
 └── Codex panel
       └── conversations/tasks
```

Excellent for **engineering**.

Not ideal as the permanent **project governance/history system** we've been building with your numbered pages.

### One interesting change: ChatGPT Work

This is actually the piece I think is more important for **your workflow** than CLI.

OpenAI now positions:

**Chat** → quick discussion  
**Work** → long multi-step work + deliverables  
**Codex** → software engineering/repos/tests  
**Codex Desktop** → local engineering + multi-agent control

And importantly, **Work exists on ChatGPT Web and works inside ChatGPT Projects**. Work chats sync between web/mobile/desktop. citeturn0search3

That means I would **not migrate your architecture/governance pages into CLI**.

I'd separate them:

```text
CHATGPT PROJECT
        │
        ├── 00001 Architecture Baseline
        ├── 00002 Product Decisions
        ├── 00003 Review / Governance
        │
        │
        └── Chat / Work
                 │
                 │ engineering package
                 ▼
          CODEX APP / VS CODE
                 │
                 ├── repo
                 ├── tests
                 ├── adversarial probes
                 ├── implementation
                 └── git commits
```

**ChatGPT Project/Work = project brain + traceability.**

**Codex App = engineering command centre.**

**VS Code Codex = code-level working bench.**

**CLI = powerful automation/terminal interface, not your page-management system.**

That distinction is especially important for the multi-project parallel work you're doing now: I wouldn't sacrifice the numbered-page/project governance structure merely to get Codex closer to the files. citeturn0search3turn0search6
