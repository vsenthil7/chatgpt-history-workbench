## F01 — BLOCKER  
## Durable schema validation accepts hostile target-owned objects

V036 says that each durable store validates its **complete expected schema**. The implementation does not capture the complete SQLite semantics.

The fingerprint currently records only:

- Basic column names, declared types, `NOT NULL`, and primary-key positions.
- Limited foreign-key table/from/to information.
- Index table and column names.
- Trigger name and table.

It does not record:

- Column defaults.
- `UNIQUE`, `CHECK`, generated-column, `STRICT`, or `WITHOUT ROWID` semantics.
- Foreign-key update/delete/match/deferred behaviour.
- Index uniqueness, partial predicates, collations, sort direction, expression columns, or origin.
- Trigger timing, event, condition, or body.

The comparison also intentionally ignores extra objects. That is valid for genuinely sibling-owned objects, but unsafe when an extra object is attached to one of the target store’s own tables.
