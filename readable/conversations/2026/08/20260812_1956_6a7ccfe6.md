## B2-UNALLOCATED-01 — HIGH

**Finding:** V012's F53 documentation closure is incomplete: the current integration contract still publishes the superseded leading-zero grammar.

**Exact files / locations**

- `02-architecture/INTEGRATION-BOUNDARIES.md:20`
- `11-decisions/ADR-013-canonical-object-boundaries-and-strict-wire-grammar.md:23` — inspected only because explicit supersession was necessary
- `07-planning/FIRST-BUILD-BACKLOG.md:47-48`

**Evidence**

`INTEGRATION-BOUNDARIES.md:20` currently says integers may be ASCII decimal strings matching:

`[0-9]+`

But accepted ADR-013 Amendment A1 at line 23 explicitly supersedes that rule with:

`(?:0|[1-9][0-9]*)`

and states that values such as `"0012"`, `"007"` and `"01"` must now be rejected.

The current backlog nevertheless states at lines 47-48 that V012 is **DONE** and that F53's wire-integer contradiction was addressed.

The traceability requirement is equally clear:

- `RTM.md:37`, **INT-005** — canonical `(?:0|[1-9][0-9]*)`;
- `RTM.md:40`, **INT-006** — canonical integer grammar and controlled rejection.

**Why defective**

`INTEGRATION-BOUNDARIES.md` is not a historical release note. It is the live integration contract presented to Platform/UraiFlow/provider implementers. It therefore tells external adapters to accept/send representations that V012 explicitly says are invalid.

This is exactly the kind of cross-document contract drift F53 was intended to close.

**Impact**

- **Product:** provider implementations can implement the wrong contract.
- **Tenancy:** no direct isolation bypass identified.
- **Integrity:** architecture, ADR, RTM and backlog disagree.
- **Operational:** a provider may send `"0012"` believing it conforms to `cgwo-consumer-v1`, while CGWO rejects it.

**Required correction**

Change `INTEGRATION-BOUNDARIES.md:20` to the canonical grammar and explicitly state that leading zeros are invalid except the single value `"0"`.

The V012 backlog should not claim F53 fully closed until all live contract surfaces use the same grammar.

**Permanent regression test**

Add a current-document consistency test that:

1. derives the current wire-integer grammar from the canonical contract/ADR;
2. checks every **live**, non-historical integration/contract document against it;
3. fails if `[0-9]+` is presented as the current `cgwo-consumer-v1` integer grammar;
4. explicitly permits historical V005/V006/V011 material to retain its historical grammar.

**Related ADR:** ADR-013 Amendment A1.

**Related RTM:** INT-005, INT-006.

**Related previous finding:** F53; earlier F24/F29/F31 are historical predecessors, not reopened merely because their historical records contain the then-valid grammar.

**Documentation impact:** `INTEGRATION-BOUNDARIES.md`; backlog V012 closure statement; any provider-facing contract documentation.

**Why defective**

- **Integrity:** wording is less precise than its governing ADR.

**Required correction**

Replace line 13 with language such as:

“Protected operations carry an explicit `TenantContext`; `tenant_id` is the enforced isolation boundary. `organisation_id`, when present, is validated Platform-owned metadata and is not independently enforced (ADR-009).”

**Permanent regression test**

A focused documentation regression should reject phrases implying organisation-level enforcement unless ADR-009 has been formally superseded.

## B3-UNALLOCATED-05 — MEDIUM

### Public typed domain-change records bypass the canonical runtime-type model

**Exact files / locations**

- `src/cgwo_core/plan_item.py:114-124` — `PlanItemChange`
- `src/cgwo_core/allocation.py:163-176` — `AllocationChange`
- public exposure confirmed by `src/cgwo_core/__init__.py:10, 33-40, 49-80`

### Evidence

Both change-record classes are frozen/slotted dataclasses but contain **no `__post_init__` validation whatsoever**.

`PlanItemChange` declares:

```python
@dataclass(frozen=True, slots=True)
class PlanItemChange:
    event_type: str
    tenant_id: str
    work_object_ref: str
    previous_state: PlanItemState
    new_state: PlanItemState
    change_reason: str | None
    item: PlanItem
```

`AllocationChange` similarly declares strings, enums, integers and a `CapacityAllocation`, but performs no validation.

I inspected all dataclasses under `src/cgwo_core`. These are the **only two domain dataclasses without `__post_init__` validation**:

```text
AllocationChange       __post_init__=NO
CapacityAllocation     __post_init__=yes
CapacityWindow         __post_init__=yes
AvailabilityDeclaration __post_init__=yes
TimeRecordProposal     __post_init__=yes
AvailabilityProposal  __post_init__=yes
PlanItemChange         __post_init__=NO
PlanItem               __post_init__=yes
TenantContext          __post_init__=yes
```

### Independent adversarial reproduction

Against the clean V012 extraction, this was accepted:

```python
PlanItemChange(
    event_type=123,
    tenant_id=object(),
    work_object_ref=None,
    previous_state="X",
    new_state="Y",
    change_reason=7,
    item="not-item",
)
```

Result:

```text
ACCEPTED
```

And this was also accepted:

```python
AllocationChange(
    event_type=123,
    tenant_id=None,
    plan_item_ref=object(),
    resource_ref=7,
    previous_state="X",
    new_state="Y",
    allocated_minutes=True,
    consumed_minutes_before="0",
    consumed_minutes_after=-1,
    allocation="not-allocation",
)
```

Result:

```text
ACCEPTED
```

This includes the specifically prohibited Python ambiguity:

```text
allocated_minutes=True
```

where ADR-012 says `bool` must not enter an `int` field.

### Why defective

ADR-010:11 states that:

> every enum-, date-, int-, str- and aggregate-typed field is validated for its runtime type on every construction path

ADR-012:12 strengthens that to **canonical exact primitive types**.

RTM `DOM-008` similarly claims malformed enum/date/int/str/aggregate fields are rejected on **every construction path**.

But these two domain objects form a completely unguarded construction path.

The generated records returned from `transition_plan_item()`, `transition_allocation()` and `consume_allocation()` happen to be populated with valid values. That does **not** satisfy the broader construction guarantee because direct construction of these publicly exported domain records is accepted.

### Product / tenancy / integrity / operational impact

**Product:** the public domain model contains two objects operating under a weaker contract than every neighbouring domain object.

**Tenancy:** a fabricated `PlanItemChange`/`AllocationChange` can contain arbitrary or mismatched tenant labels. These records are not currently authorization inputs, so I did **not** reproduce a tenant-isolation bypass.

**Integrity:** this directly contradicts ADR-010, ADR-012 and RTM DOM-008. It can also create internally contradictory audit/change facts.

**Operational:** ADR-008 deliberately positions these records for future audit/review/learning consumption. If persisted or dispatched later without correction, malformed history can enter that downstream slice.

### Required correction

Add canonical validation to both change-record classes, preferably via `__post_init__`.

At minimum validate:

**`PlanItemChange`**

- exact `str` for `event_type`;
- exact canonical `tenant_id`;
- exact canonical `work_object_ref`;
- exact `PlanItemState` for previous/new state;
- exact `str | None` change reason;
- aggregate validation for `item`.

**`AllocationChange`**

- exact strings for all refs/event/tenant;
- exact `AllocationState`;
- exact `int` for every quantity, rejecting `bool`;
- aggregate validation for `allocation`.

The records should also validate **relational consistency**, not merely individual field types:

- record tenant == resulting aggregate tenant;
- record work/allocation references == resulting aggregate references;
- `new_state` == resulting aggregate state;
- allocation quantities == resulting allocation values;
- consumed-before/after are logically compatible with the transition.

Otherwise a correctly typed but false audit record remains constructible.

### Required permanent regression test

Add a direct-constructor adversarial matrix for **both record types** covering:

- raw strings instead of enums;
- arbitrary objects;
- `str`/`int` subclasses;
- spoofed `__class__`;
- `bool` in integer fields;
- malformed aggregate values;
- tenant/reference mismatch;
- new-state/resulting-aggregate mismatch;
- quantity mismatch.

Also retain positive tests proving records emitted by genuine transitions remain valid.

Mutation testing must kill removal of every new guard.

- **ADR-010** — every typed field/every construction path
- **ADR-012** — canonical primitive trust model

### Related RTM

`allocation.py:14-16` repeats:

> Quantity-bearing states (`PARTIALLY_CONSUMED`, `CONSUMED`, `OVERRUN`) are reachable only through `consume_allocation`.

```text
rehydrate PARTIALLY_CONSUMED -> ACCEPTED, consumed=10

```

That behaviour is **correct according to the later governing decision**.

`PlanItem` already documents this accurately:

It was not.

**Tenancy:** no tenancy defect.

**Integrity:** accepted ADR/current source comments misdescribe an intentionally public construction pathway.

unless accompanied by the rehydration/direct-construction qualification.
