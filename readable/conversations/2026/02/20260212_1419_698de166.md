Here is how it works in principle:

In a group chat:

I do NOT dynamically change behaviour based on who is paying in that room.

• The model powering that group  
• The workspace / host account tier  
• The feature permissions of that group environment  

Not based on each individual participant’s subscription.

Case 1 — Group created by a Plus user  
→ The group runs on that Plus model capability.  
→ Free users inside the group still see responses generated by the Plus-tier model.  

Case 2 — Group created by a Free user  
→ The group runs on Free-tier model limits.  
→ Even if a Plus user joins, the group does not magically upgrade.  

Case 3 — Team / Enterprise workspace  
→ The group follows that workspace’s model, tools, and policy configuration.

Memory in group mode stays OFF regardless of who pays.  
That is a privacy rule, not a subscription rule.

So behaviour differences you may see:

• Message length limits  
• Tool availability (file uploads, advanced tools, etc.)  
• Model reasoning depth  
• Rate limits

I don’t detect:
“Ah this user is paying, I will be smarter now.”

The environment decides capability — not the individual inside it.
