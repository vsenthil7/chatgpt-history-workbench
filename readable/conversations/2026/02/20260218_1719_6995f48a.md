Design choice
We record "pending" requests on-chain in a shared queue and mint on approval to avoid multi-signer flows. Keep transitions centralized and avoid cross-module state mutation unless your grant module exposes explicit helpers.

# 🧬 Concept 4 — Abilities Audit (Very Important)

Move abilities:

| Ability | Meaning |
|----------|---------|
| key | Can live on chain |
| store | Can be inside another struct |
| copy | Can duplicate |
| drop | Can be silently discarded |

If you allow `copy` on Grant →  
You break conservation.

If you allow `drop` →  
You may silently destroy assets.

Enterprise-grade design means:

- Caps: `key | store`
- Grants: `key` only
- No accidental `copy | drop`

This is subtle but critical.
