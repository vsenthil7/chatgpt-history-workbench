 **ENG-GOV Lens: Corruption-Detection Architecture** **Goal:** *Respect privacy, expose financial networks, make every claim trace to evidence, and produce actionable leads (not “accusations”).*
 
Below is the full “Big I” blueprint — end-to-end — with zero hand-waving.
  
# 0) The Non-Negotiable Principles (invariants)
 
 
1.  
**Evidence-first** Every entity/edge/claim must link back to a primary source (document hash + storage pointer + capture time).
 
 
2.  
**No doxxing** Never publish personal phone numbers, exact home addresses, minor children data, victim/witness identities, or sensitive case party details.
 
 
3.  
**Network transparency > personal exposure** We reveal *relationships of money/benefit/control*, not private life.
 
 
4.  
**Probabilistic truth with confidence** Identity resolution and “connections” must be confidence-scored; low-confidence links are quarantined or shown only to auditors.
 
 
5.  
**Outcome labels, not stigma** Case records must clearly show “accused / pending / acquitted / convicted / disposed / stayed” with dates.
 
 
6.  
**Layered access (least privilege)** Public sees safe summaries; accredited auditors see deeper; full details require legal process.
 
 
7.  
**Audit logging everywhere** All accesses, queries, exports are logged and tamper-evident.
 
 

  
# 1) What this system actually produces
 
## Outputs (products)
 
 
1.  
**Network Graphs** Politician ↔ companies ↔ beneficial owners ↔ contracts ↔ donations ↔ properties ↔ related parties ↔ cases (with statuses) *with time dimension.*
 
 
2.  
**Risk Signals (not accusations)**
 
 

 
 
- “Unusual asset growth vs declared income band”
 
- “Repeated contracts to linked entities”
 
- “Same beneficial owner across multiple vendors winning tenders”
 
- “High-proximity related-party transactions”
 
- “Officer transfer clusters after investigations” (optional; sensitive)
 

 
 
1. **Case Kits (bundle of evidence)** A downloadable evidence package for an auditor/journalist/lawyer:
 

 
 
- Sources list + hashes
 
- Timeline
 
- Graph snapshot
 
- Key anomalies
 
- Confidence & limitations
 

  
# 2) The 3-Layer Transparency Model
 
## Layer A — Public Safe Graph (default)
 
**Shows**
 
 
- Politician/public figure profile
 
- Asset trend **ranges** (not exact address-level detail)
 
- Company affiliations (director/shareholder/beneficial owner where legally public)
 
- Contract award counts + amounts (if public)
 
- Donation aggregates (if public)
 
- Court case status (high-level, with case IDs where allowed)
 
- Network view with **redacted nodes** for private persons unless strongly relevant and legally public
 

 
**Hides**
 
 
- exact addresses
 
- phone/email
 
- children
 
- victims/witnesses
 
- detailed police narratives
 
- any low-confidence identity matches
 

 
## Layer B — Trusted Auditor Graph (journalists/NGOs/researchers)
 
**Adds**
 
 
- more granular document fields
 
- stronger identity resolution hints
 
- relationship explanations + edge provenance
 
- “why this is flagged” explanations
 
- controlled export (watermarked, rate-limited)
 

 
## Layer C — Full State / Legal Access (warrant/authority)
 
**Adds**
 
 
- protected datasets (if legally permissible)
 
- deep linkability across sensitive sources
 
- full address history, banking SAR-style summaries (only with lawful basis)
 
- witness protection redactions are still enforced
 

  
# 3) Data Sources (the “inputs”) — and how we treat them
 
We only ingest **legally accessible** data. Split into tiers:
 
## Tier 1: Open & structured (low legal risk)
 
 
- Procurement/tender portals (award notices, vendor names, amounts, dates)
 
- Company registries (directors, filings, charges, PSC/beneficial ownership if available)
 
- Election affidavits (assets, liabilities, cases)
 
- Gazettes / official orders (appointments, transfers, notifications)
 
- Parliamentary/assembly transcripts (votes, questions)
 
- Court cause lists / judgments (public)
 
- Sanctions/blacklists (vendor blacklisting, debarments)
 

 
## Tier 2: Public but messy (PDF/scans, medium risk)
 
 
- Affidavit PDFs, scanned filings
 
- Land/property registry extracts (where public) — **address redaction mandatory**
 
- RTI responses published by requesters
 
- Media archives (only as secondary signals, never as sole evidence)
 

 
## Tier 3: Restricted / sensitive (high legal risk)
 
 
- Police FIR narratives, charge sheets in full (varies by jurisdiction)
 
- Tax records, banking, telecom metadata
 
- Intelligence data **We do NOT use Tier 3 unless there is a lawful access framework and strict Layer C controls.**
 

  
# 4) Core Data Model (graph schema)
 
Everything becomes a graph with typed nodes & edges.
 
## Nodes
 
 
- **Person** (public_figure / civil_servant / private_person)
 
- **Organization** (company / NGO / party / trust / partnership)
 
- **Asset** (property_unit / vehicle / security / trust_interest) *(public-safe only as category + region)*
 
- **Contract** (tender/award)
 
- **Case** (court_case / criminal_case / civil_case)
 
- **Filing** (affidavit, company filing, gazette, judgment)
 
- **Transaction** (donation, related-party transaction record, grant, subsidy)
 
- **Role** (director, shareholder, minister, officer_posting, contractor)
 

 
## Edges (with direction, weight, time)
 
 
- Person **OWNS_BENEFICIALLY** Org (pct, confidence)
 
- Person **DIRECTOR_OF** Org (start/end)
 
- Org **WON_CONTRACT** Contract (amount, date)
 
- Contract **ISSUED_BY** Agency/Dept
 
- Person **RELATED_TO** Person (relation_type, confidence, source-limited)
 
- Org **PAID** Person/Org (if disclosed legally)
 
- Person **FILED** Affidavit (date)
 
- Person **INVOLVED_IN** Case (role: accused/complainant/witness) *(witness often redacted)*
 
- Org **HAS_CHARGE** (secured lending / MCA charge)
 
- Asset **HELD_BY** Person/Org *(public-safe: coarse location only)*
 

 
Every edge stores:
 
 
- `source_doc_id`
 
- `source_url` (if safe)
 
- `capture_timestamp`
 
- `extract_method` (parsed/ocr/manual)
 
- `confidence_score`
 
- `valid_from`, `valid_to`
 

  
# 5) Ingestion Pipeline (from raw web to trustworthy graph)
 
## Step 5.1 — Acquire
 
 
- Scheduled crawlers (daily/weekly)
 
- Manual uploads (auditors can add PDFs)
 
- Change detection (hash + diff)
 

 
## Step 5.2 — Normalize
 
Convert everything into canonical JSON:
 
 
- standard date formats
 
- currency normalization
 
- party name normalization
 
- organization name normalization
 

 
## Step 5.3 — Extract (PDF → fields)
 
 
- deterministic extraction where possible
 
- OCR only when unavoidable
 
- capture bounding boxes + page refs for explainability
 

 
## Step 5.4 — Evidence vault
 
Store originals in immutable storage:
 
 
- content-addressed (SHA-256)
 
- versioned
 
- retention policy
 

 
## Step 5.5 — Graph write
 
Insert nodes/edges with provenance.
  
# 6) Identity Resolution (hardest part) — done safely
 
We never “force” identity matches. We compute them.
 
## Step 6.1 — Candidate generation
 
For a new name:
 
 
- exact match on normalized name + district/state
 
- fuzzy match on name + father/spouse name (where legally present)
 
- match on org director IDs (if registry provides)
 
- match on filing signatures/IDs
 

 
## Step 6.2 — Scoring model (transparent, auditable)
 
Score components:
 
 
- name similarity (phonetic + edit distance)
 
- co-occurrence (same org + same timeframe)
 
- address region match (coarse)
 
- relative name match (spouse/father) where legal
 
- unique identifiers if public (rare)
 

 
Output:
 
 
- `match_confidence ∈ [0,1]`
 
- explanation vector (“why matched”)
 

 
## Step 6.3 — Safety gating
 
 
- `<0.7` → **quarantine** (auditor-only)
 
- `0.7–0.9` → show with warning banner
 
- `>0.9` → eligible for public layer (still redacted where needed)
 

 
## Step 6.4 — Human review workflow
 
Auditors can:
 
 
- confirm match
 
- reject match
 
- request more evidence All actions logged.
 

  
# 7) Privacy-Respecting Redaction Engine (policy kernel)
 
This is where most systems fail. We do it as a deterministic rules engine.
 
## Step 7.1 — Redaction taxonomy
 
 
- **Direct identifiers:** phone, email, Aadhaar/PAN, bank acct
 
- **Location identifiers:** house number, street, school name
 
- **Protected persons:** minors, victims, witnesses (default redact)
 
- **Sensitive cases:** sexual offences, juvenile matters, domestic violence
 

 
## Step 7.2 — Field-level policies
 
Example policy:
 
 
- Public: show property as “Residential property, Patna district” not exact address
 
- Auditor: show ward/tehsil but still not house number
 
- State: exact address only with lawful basis
 

 
## Step 7.3 — Edge publication rules
 
 
- Person↔Person family edges only published if: 
 
  - both are public figures, OR
 
  - financial linkage exists (shared beneficial ownership, transfers, contracts), AND
 
  - source is legally public, AND
 
  - confidence high
 

 
 

 
Otherwise: keep in auditor layer.
  
# 8) Financial Network Exposure (the “anti-hiding” methods)
 
This is the core value: corruption hides in proxies. We map proxies without doxxing.
 
## 8.1 Beneficial ownership inference (when registry is weak)
 
We infer “control likelihood” via:
 
 
- shared directors across vendor + relative companies
 
- repeated co-appearance of a name in filings
 
- same auditor/registered agent clusters (careful: weak signal)
 
- timing patterns: company formed → wins contract fast
 
- related-party disclosures (if available)
 

 
**Output:** “Control Likelihood Edge” with low/medium/high confidence and explanations.
 
## 8.2 Related-party transaction detection
 
We flag:
 
 
- payments to entities sharing directors/owners with the decision-maker’s known network
 
- loans at unusual terms
 
- repeated consultancy fees to linked persons
 

 
## 8.3 Contract concentration and favoritism metrics
 
For each dept:
 
 
- Herfindahl index of vendor concentration
 
- top vendor share changes over time
 
- “new vendor wins large award quickly”
 
- “single-vendor repetitive awards” patterns
 

 
## 8.4 Asset growth anomaly signals (privacy-safe)
 
We don’t need addresses. We track:
 
 
- declared asset value bands over time
 
- growth rate vs declared income band
 
- sudden jumps coinciding with office changes / contract spikes
 

 
Flag as “needs review,” not “illegal.”
  
# 9) Scoring Engine (how we prioritize leads)
 
We compute multiple independent risk scores:
 
## 9.1 COI Risk Score
 
Signals:
 
 
- directorship/shareholding in vendor companies
 
- spouse/dependent links to vendors
 
- repeated contracting to linked networks
 
- unexplained asset jumps around decisions
 

 
## 9.2 Procurement Risk Score
 
Signals:
 
 
- high vendor concentration
 
- short tender windows
 
- single-bid awards
 
- repeated awards to a newly formed entity
 

 
## 9.3 Network Proximity Score
 
Graph distance from a public official to a vendor:
 
 
- 1 hop: direct ownership/directorship
 
- 2 hop: spouse/close relative controls company
 
- 3 hop: associate controls company Each hop adds uncertainty; use confidence weighting.
 

 
## 9.4 Evidence Strength Score
 
Weighted by:
 
 
- primary sources count
 
- recency
 
- match confidence
 
- contradicting records present/absent
 

 
**Important:** No single score triggers public accusation. Scores only decide what humans should look at first.

5. Compute: 
 
  - vendor concentration spike
 
  - network proximity 2 hops (minister → spouse → charitable trust board member → vendor director)
 

 
 
6. Evidence drawer shows filings + tender notices
 
7. Public layer displays: 
 
  - “Potential conflict network detected (confidence medium).”
 
  - shows vendors + contract amounts
 
  - redacts private-person node names unless already public
 

 
 
8. Auditor layer can see the intermediate nodes and the match explanation
 
9. Auditor can confirm identity match or reject it
 
10. If confirmed and evidence strong, publish a more explicit relationship graph (still no doxxing)
