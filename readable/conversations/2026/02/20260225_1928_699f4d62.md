**Goal:** build a single PTB that (1) gets ingredients, (2) makes dough, (3) mints/transfers the Flag to you. The contract is trivial, so the “challenge” is basically **PTB wiring + using return values**. citeturn0search0

**Estimated completion time:** 15–25 minutes.

---

## 1) Set package id (from the challenge)
```bash
PKG=0x7661363fdfe4cd602711244a8501c17e756a5304bcce0918efcef4af98c09291
```
(That’s the deployed package you posted.) citeturn0search0

---

## 2) Dry-run the PTB (no gas spent)
This uses `--assign` to capture the tuple returned by `get_ingredients()`, then uses `.0 .1 .2 .3` to pass the four values into `make_dough`. The PTB docs show this “dot-index” style for assigned results. citeturn1view0turn2view3

```bash
iota client ptb \
  --move-call "$PKG::ptb::get_ingredients" \
  --assign ing \
  --move-call "$PKG::ptb::make_dough" ing.0 ing.1 ing.2 ing.3 \
  --assign dough \
  --move-call "$PKG::ptb::get_flag" dough \
  --gas-budget 50000000 \
  --dry-run
```

If `--dry-run` succeeds, you’re ready to execute for real. (`--dry-run` is recommended for complex PTBs to avoid wasting gas.) citeturn1view0

---

## 3) Execute (actually capture the flag)
Same command, just remove `--dry-run` (optionally add `--summary`):

```bash
iota client ptb \
  --move-call "$PKG::ptb::get_ingredients" \
  --assign ing \
  --move-call "$PKG::ptb::make_dough" ing.0 ing.1 ing.2 ing.3 \
  --assign dough \
  --move-call "$PKG::ptb::get_flag" dough \
  --gas-budget 50000000 \
  --summary
```

---

## 4) Find the **Flag object id** (for “Claim your NFT reward”)
After execution, grab the created object from your owned objects list and look for the type ending in `::ptb::Flag`:

```bash
iota client objects
```

Then confirm the one you suspect:
```bash
iota client object <FLAG_OBJECT_ID>
```

You want the **newly created** object whose type matches the module (`$PKG::ptb::Flag`) and is owned by your address.

That `<FLAG_OBJECT_ID>` is what you paste into the site’s “Flag Id”. citeturn0search0
