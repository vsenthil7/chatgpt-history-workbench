## Why batch processing is clever

During production, don't let every successful LLM answer mutate company knowledge immediately.

At night—or at configurable intervals—the **Knowledge Consolidation Pipeline** can examine:

- repeated LLM escalations;
- semantically similar requests;
- expensive request classes;
- RAG misses;
- CLM failures;
- corrected answers;
- human-approved answers;
- wrong RAG answers;
- wrong CLM answers;
- high-latency decisions.

Then classify them.

**Stable fact?** → structured store/RAG.

**Deterministic decision?** → rule/policy-as-code candidate.

**Frequently repeated semantic reasoning?** → CLM training/evaluation candidate.

**Temporary/current information?** → RAG with expiry/freshness.

**Rare complicated problem?** → leave with frontier LLM.

**Dangerous/high-risk judgement?** → continue frontier/human verification regardless of cost.

So the system learns **where intelligence should live**.
