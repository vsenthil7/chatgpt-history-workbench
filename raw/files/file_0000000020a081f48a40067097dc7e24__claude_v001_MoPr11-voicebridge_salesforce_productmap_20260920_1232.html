2 · Context — what this product is, and how it got here

How to use this section. Read it once before the diagrams. It carries the six facts that make the pictures legible; everything after it assumes them.

The product. VoiceBridge CTI is a Salesforce AppExchange application for mid-market B2B sales teams: a softphone that lives in the Salesforce utility bar, click-to-dial from any record, automatic logging of every call (and, in the pitch, every WhatsApp thread) back onto the Contact or Lead, plus lightweight cadences, coaching scorecards and Flow actions. It is product P02 of a twelve-product marketplace portfolio, built solo.

How it was built. Fifteen numbered code releases between 13 and 20 September 2026, each one packaged, re-extracted and re-verified from its own zip. Every release is gated on 100% statement, branch, function and line coverage with no coverage pragmas — a standing portfolio rule (D13) — and on a release-evidence pack bound to the package hash.

What three reviews found. Five internal cold-review passes found roughly forty defects inside code that already had 100% coverage. An external review (ChatGPT, 13 September) returned REJECT with fourteen findings, five of them blockers. A second independent review (Perplexity, 16 September) returned HOLD — re-platform or pivot, with six further findings and one strategic fact nobody had recorded: the Salesforce API the whole in-org surface depends on is being retired.

Where that leaves the build. Version 0.28.0 closed five of the six Perplexity findings and four worse defects that the fixes themselves exposed. The code is now, by any reasonable reading, an engineering-complete service — and it has still never placed a telephone call, never written a record into a real Salesforce org, and never run against a real database. Those two sentences are both true at once, and holding them together is the point of this document.

The vocabulary used on every diagram

StatusWhat it means here — the test applied to every single box
Built and proven The code exists and the evidence exists today, in a form you can re-run yourself: an automated test, a build gate, a database check, or the release evidence pack. Nothing in this state depends on a system we do not have.
Built, unproven live The code exists and is fully tested, but every counterparty in the test is a double we wrote. It has never met a real Salesforce org, a real PostgreSQL server, a real carrier or a real browser inside a real utility bar. This is not a quality judgement on the code; it is a statement about what has been observed.
Not built The component does not exist. In every case the reason is a decision that has not been made or a commercial relationship that does not exist — never an unsolved technical problem.
Not ours Salesforce's, a vendor's, or the operator's. Shown because the mechanism is unreadable without it.

Each state is written on the box as well as coloured, so the diagrams survive greyscale printing and do not depend on colour vision.

CompletedWhat it doesEvidence you can run today
The in-org softphone surface The panel, its adapter bundle and its configuration are served by the application itself. Until v0.28.0 the page the CallCenter definition pointed at was never served at all — a live utility bar would have loaded a 404 with no error anywhere. test/widget.test.ts boots the real app, fetches the real URL, asserts both script tags and the injected config, and parses the CallCenter metadata to prove the path resolves to a registered route.
Identity and session lifecycle OAuth on an External Client App with PKCE, a signed session carrying a token id and a per-user epoch, logout, revoke-all, and role assignment that kills the target's existing sessions. test/sessionLifecycle.test.ts, test/authBoundary.test.ts — including that a pre-v0.28.0 token shape is refused rather than grandfathered.
Web hardening Content-Security-Policy with a Salesforce-only frame-ancestors allowlist, HSTS, nosniff, referrer and permissions policies, a 100 kB body cap, an inbound timeout, request ids, and rate limits that hold across instances because the counter lives in the database. test/hardening.test.ts pins every header on JSON, HTML, 404 and 401 responses, and proves the org budget holds across two separate app instances sharing one repository.
Encryption at rest AES-256-GCM envelopes over both Salesforce tokens, with a versioned key ring, per-org additional authenticated data, and a rotation sweep. The trust page has claimed this since S10; it became true on 20 September. test/tokenCipher.test.ts plus a conformance test on both repository implementations asserting the persisted bytes never contain the plaintext.
Tenant isolation at the database Row-level security, forced on every org-scoped table, compared against a tenant context set inside each transaction. A deliberately misconfigured application reads nothing. db/checks/rls-smoke.sql runs in CI as a non-superuser role and proves the cross-tenant read and write are both blocked with the application absent.
Tamper-evident audit trail A sha256 hash chain per org, append-only at the database, verifiable by the customer through an endpoint, and exempt from the record cap because an audit log with a ten-thousand-row memory is not one. test/auditChain.test.ts (tampered, deleted and re-ordered rows each detected at a named position) and db/checks/audit-append-only.sql.
Auto-logging to Salesforce (our half) Phone matching through the platform's own phone index, then one Task per call upserted on our external id, so a retry updates rather than duplicating. More than one matching record is reported as ambiguous and written unattached — never guessed. test/crmWriteBack.test.ts drives the real route through the real writer over a local HTTP server answering the shapes Salesforce really returns.
A durable, self-draining outbox A failed CRM write queues and is retried by a leader-elected background worker with exponential backoff and a dead-letter threshold. Before v0.28.0 the queue only drained if a human pressed a button. test/outboxWorker.test.ts black-holes Salesforce for ten simulated minutes and proves the queue drains unattended on recovery, with leadership handing over on lease expiry.
Pre-dial refusal E.164 normalisation against fifteen country rule sets, an org blocklist and a do-not-call registry seam — all consulted before a provider would ever be asked, so a refused number never costs a carrier attempt. test/numbers.test.ts — 25 cases including the negative ones, plus the admin-only routes.
Operations tooling Structured JSON logs with secret redaction, RED metrics per route pattern, a Prometheus endpoint, an error sink, the published 99.5% expressed as an error budget with importable burn-rate rules, a real blue/green deployment script with automatic rollback, and a disaster-recovery drill script. test/observability.test.ts, test/reviewSprint.test.ts (the workflow and script shapes are asserted, not assumed).
The claim-to-test gate Every sentence the product publishes about its own behaviour maps to a claim id, and every claim id must be carried by a tagged test. An unbacked sentence fails the build. test/claims.test.ts walks both directions over 34 claims; docs/claims-registry.md is generated from the same list.
Release integrity The evidence pack is bound to the package hash, and the comparison is symmetric: a source file the evidence never saw, or a test suite on disk the run never executed, both fail the release. npm run evidence:check in CI and before every deploy; the gate was executed from the packaged zip and its own false positive fixed before release.

9 · What is not completed, and exactly why

How to use this register. Sorted by what blocks it, not by size. Nothing in this table is blocked on engineering difficulty; every row is waiting on a ruling, a commercial relationship, or a system that has to be provisioned before anyone can watch it work.

9.1 · Blocked on a decision only Senthil can make

Not completedWhy it is not builtUnblocked by
Placing a real telephone call No telephony adapter exists. The seam an adapter must satisfy is built and tested, and the simulator behind it labels every call simulated: true on every surface — but nothing dials. This was left deliberately: the provider choice sets per-minute cost and therefore the pricing floor in billing.ts, so it is a commercial decision, and building an adapter for an unchosen provider would mean inventing one and then testing the invention. D-V5 — name the carrier on landed cost per minute
Inbound calls, screen pop, call-quality telemetry All three need the same adapter plus an inbound webhook whose signature scheme and event vocabulary are provider-specific. The routing and screen-pop logic on our side already exists. D-V5
Call recording and consent Needs the carrier, a storage location and a per-jurisdiction announcement policy. The audit chain and retention sweep it would hang on are built. D-V5 + a storage decision
WhatsApp — the whole omnichannel half Never built. The product accepts a message event if something else posts one, and logs it as a Task, but there is no provider client, no number onboarding, no opt-in ledger, no 24-hour window enforcement and no templates. In v0.28.0 the claim was withdrawn from the help centre rather than left published, so the product no longer says it does something it does not do. D-V6 — build it, or drop the ambition
Which platform the in-org surface targets Everything in the Salesforce column is built on Open CTI, which is in maintenance mode, ends life on 28 February 2028, and is closed to newly created Agentforce Service orgs. Against a five-to-nine month listing lead time, a submission started today would list onto a surface with under a year of supported life. No further work was done on that surface beyond making it correct. D-V9 then D-V8
A usable financial model The current model never reaches breakeven inside eighteen months, its $600 ARPU contradicts its own 50–500 seat ICP by a factor of 2.5–5, it has no per-minute cost line for a telephony product, and its top plan limit equals the top of the ICP with no tier to grow into. D-V7 — cost and funding assumptions
An honest story count Twenty stories promising click-to-dial and automatic logging are still counted as Done. Both external reviewers, and this release, recommend reclassifying them to "Code-complete (unproven)", which moves the reported position from 96/100 to 76/100. The definition-of-done clause is already recorded; only the reclassification itself is outstanding. D-V4
Any evidence that a customer wants this Discovery interviews were parked portfolio-wide on 10 September (D13) and have never been run. Every demand claim in the workbook is a desk assumption. The second reviewer calls this the root cause of the entire review, and it is the cheapest item on the whole list. D13 — fifteen conversations

The one thing to take away if you read nothing else

The gap between this product and a shippable one is not a code gap. It is five operator days against a developer org and a database, plus six decisions that cost nothing to make but cannot be made by an engineer. Six months of further engineering with the current inputs would not move a single cell in the evidence column.

10 · The five operator steps that change the picture

How to use this section. These are the shortest paths from amber to green in figures 1 and 3. Each is written as an executable step in docs/salesforce-dev-org-guide.md, and each one has a corresponding manual test case in the companion test workbook.

StepWhat it needsWhat it would prove, and what turns green
O6A PostgreSQL 16 instance That the repository conformance suite behaves identically against a real database — caps, cascades, unique indexes and the atomic counter under concurrency. Closes R-V11 and R-V13, and turns the storage and isolation rows green.
O7A Salesforce developer org + the package deployed That a Task really is created once and updated on retry, that the phone match finds the right Contact, and that a Salesforce outage leaves the note safe and drains afterwards. This is the single highest-value hour available.
O7bThe same org, utility bar open That the softphone panel actually renders inside Salesforce and the adapter loads. This is the step that would have caught the defect that survived three reviews and eight releases.
O9Live PostgreSQL, application role That row-level security blocks a cross-tenant read with the application deliberately misconfigured, that audit rows refuse to be updated or deleted, and that a dump restores with matching checksums.
O10A deployed service + any metrics backend That the burn-rate alert fires and clears during a deliberate ten-minute Salesforce outage, and that the outbox drains without anyone watching. Turns the operations row green.

11 · Glossary

TermMeaning as used in these diagrams
Open CTIThe Salesforce API for embedding a third-party softphone in the Lightning UI. In maintenance mode; end of life 28 February 2028.
Partner TelephonyThe Service Cloud Voice model Salesforce directs third-party carriers to; the supported replacement for Open CTI.
CallCenter definitionThe metadata record that tells a Salesforce org which URL to load as its softphone.
External Client App (ECA)The OAuth client type that replaced Connected Apps, which can no longer be created as of Spring '26.
SOSLSalesforce Object Search Language. FIND {digits} IN PHONE FIELDS uses the platform's own phone index, replacing an unindexed trailing-wildcard scan.
Upsert on an external idWriting a record keyed on our own identifier, so the platform decides insert-or-update and a retry cannot create a duplicate.
OutboxA durable queue of CRM writes that failed, drained in order by a background worker with backoff and a dead-letter threshold.
Row-level security (RLS)PostgreSQL policies that filter every row by the tenant context set inside the transaction, so isolation is the database's job rather than the application's.
Dead letterA queued write parked after too many failures: visible in health output, never retried automatically.
Burn rateHow fast an error budget is being consumed. A fast burn pages a human; a slow burn opens a ticket.
E.164 / DNCThe international phone number format; a do-not-call registry that must be consulted before dialling.
O-stepAn operator step: work that cannot be done in code because it needs a live system.
D-VnAn open decision recorded in the sprint tracker, with its owner and what it blocks.
F-Pn / VB-CR-n / F-VnFindings from the Perplexity review, the ChatGPT review, and the internal cold reviews respectively.
