## 20. Most cost-efficient pipeline for the 500-hour archive

**Design (all AVAILABLE NOW except where noted):**

1. **STT** → use **Batch STT** (₹30/hr); add **diarization only where the audio is genuinely multi-speaker** (meetings/interviews) — ₹45/hr. For a 500-hr mixed archive, assume ~60% needs diarization. Model: Saaras (V3/V4) [cite:84fd9e82].
2. **Preserve raw transcript** → store the raw STT output unchanged (no Sarvam cost).
3. **LLM clean-up/structuring** → **`glm5.3-flash`** (₹13.5/₹2.7/₹45) or **`deepseekv4-flash`** for a cheap first pass (fix ASR errors, add speaker labels/timestamps, normalise code-switching). Use `sarvam-105b` if you need maximum Indic fidelity on the cleanup itself.
4. **Summary + topics + decisions/action items + quotes + metadata** → one **structured-output pass** on **`sarvam-105b`** (tool-calling / JSON schema) so a single call returns summary, topics, decisions, action items, quotes and metadata [cite:1a6f5b42].
5. **Searchable metadata** → the JSON from step 4 plus a local keyword/BM25 index. Sarvam publishes **no embeddings API price**, so semantic search would use an LLM call — **UNKNOWN** as a separate line item.

**Cost for 500 hours:**

| Stage | Cost |
|---|---|
| STT (base, ₹30/hr) | ₹15,000 |
| STT with diarization (₹45/hr) | ₹22,500 |
| Cleanup pass (`glm5.3-flash`) | ₹108 |
| Analysis pass (`sarvam-105b`) | ₹219.60 |
| **Total — base STT + both LLM passes** | **~₹15,328** |
| **Total — diarized STT + both LLM passes** | **~₹22,828** |

The whole LLM layer is **~₹328 (≈1.4–2% of total)**. So the cost lever that matters is **whether you diarize**, not which LLM you pick. Budget **~₹15,000–₹23,000** for 500 hours.

## 22. Reasons NOT to use universal credits for all three flows

**AVAILABLE NOW unless noted.** Mostly there's no blocker — but the precise restrictions are:

1. **Indus Chat/Cowork are excluded** from the universal wallet (Q9). If you want that chat/agent experience, it's a separate per-seat subscription [cite:6ffb3188].
2. **Rate limits are per-account and plan-bound.** Starter = 60 req/min; 105B = 40 req/min; batch STT = 20 req/min; WebSocket STT = 20 concurrent [cite:7c0d7782]. Large parallel LLM analysis of many transcripts on Starter will hit 40 req/min on 105B — throttle or upgrade.
3. **`max_tokens` cap is plan-bound** (Starter 4096) — caps single-response length [cite:1a6f5b42].
4. **Context windows:** `sarvam-105b` = 128K, `sarvam-105b-conversations` = 32K. A transcript longer than the window must be chunked or routed to a 1M-context model (`deepseekv4-flash`, `glm5.3`) [cite:4edee00d]. This is the most likely technical gotcha for long calls.
