# 04/10/2026 19:04 — The New “Build It” Competitor

**Yes. These questions must be part of the TalkProof competitor model.** “Claude can build software” is far too shallow.

The competitor isn't Claude or Codex individually. It is a new **production method**:

> **A person/team + AI coding agents + APIs + open source + cloud can increasingly substitute for buying SaaS.**

And this market is already becoming measurable: Stack Overflow reports AI-tool usage among surveyed developers rose from 44% in 2023 to **79% in 2025**, while its April 2026 pulse found **59% using AI agents**. Anthropic's 2026 enterprise report says more than 9 in 10 surveyed organizations use AI to assist coding and 86% are deploying coding agents for production code. [Stack Overflow Blog](https://stackoverflow.blog/2026/09/30/getting-ready-for-2026-results-a-look-back-on-developer-survey-findings/?utm_source=chatgpt.com)

SlashData has even started tracking a new category called **“builders”**: people without traditional developer backgrounds using AI to build applications/services. [SlashData](https://www.slashdata.co/post/rise-of-the-builder-developer-trends-q3-2026?utm_source=chatgpt.com)

So this is absolutely a TalkProof competitive threat.

## Who can actually use “BUILD IT”?

There are several very different populations.

| Builder | Could build TalkProof-like system now? | What they could realistically produce |
|---|---:|---|
| Non-technical business owner | ⚠️ Partly | prototype/basic workflow |
| Power user / analyst | ⚠️ Increasingly | internal app + integrations |
| Junior developer + AI | 🟡 Partly | substantial application, needs architecture/security help |
| Experienced full-stack developer + AI | 🟢 Yes | serious alternative |
| Senior architect/engineer + AI agents | 🟢 **Strong threat** | enterprise-style custom alternative |
| 2–5 person AI-native engineering team | 🔴 **Very strong threat** | credible competing product |
| Consultancy/system integrator + AI | 🔴 **Very strong threat** | customer-specific replacement |
| Enterprise internal IT/engineering | 🔴 **Strategically important** | “why buy TalkProof? We'll build our own.” |

This last group matters enormously.

TalkProof doesn't only have to beat Retell, NICE, Genesys, Observe.AI, etc.

It eventually has to answer a CIO saying:

> **“Why am I paying you £X per year when my existing engineers plus coding agents can assemble what I need?”**

This is exactly why your TalkProof experience is useful evidence.

You can get **58,000+ lines, 1,000+ tests, dozens of tables and hundreds of APIs** remarkably quickly.

But then you discovered the harder question:

> **Does “generated and tested” actually equal the product requirement?**

It doesn't necessarily.

Stack Overflow's 2026 research similarly finds human oversight remains important: 60% of respondents block agents from making unapproved system changes. [Stack Overflow Blog](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work?utm_source=chatgpt.com)

# Running cost is where this gets interesting

There are **two costs**, and we should never mix them.

### 1. Cost of creating/maintaining the software

An AI-native solo builder might pay for:

- one or more premium coding agents;
- GitHub;
- cloud development/testing;
- monitoring;
- CI/CD;
- occasional specialist services.

That could be **hundreds rather than tens of thousands of pounds per month** at small scale.

The AI itself is becoming a surprisingly small part of software creation.

### 2. Cost of actually operating TalkProof-like workloads

This doesn't disappear.

You still pay for:

```text
Phone minutes
+ phone numbers
+ SIP/telephony
+ STT
+ TTS
+ LLM inference
+ storage
+ databases
+ bandwidth
+ video/media
+ email/SMS/WhatsApp
+ timestamps/blockchain
+ observability
+ backups
+ cloud compute
```

And if the customer BYO-providers, **the customer may directly bear much of this variable cost**.

That makes TalkProof's provider-neutral architecture strategically more important, not less.

# Maintenance is the real trap for “I'll build it myself”

Generating version 1 is becoming cheap.

Owning it for five years isn't automatically cheap.

Consider what happens after launch:

```text
Twilio changes API
Meta changes WhatsApp rules
LLM model deprecated
Claude/OpenAI pricing changes
Security vulnerability discovered
Python package vulnerability
iOS/Android update
Browser changes
Stripe API version changes
Regulation changes
Customer wants SSO variation
Provider outage
Database grows 100×
Model quality regresses
Prompt behaviour changes
Attack technique changes
Employee who built it leaves
```

Someone—or increasingly some **AI maintenance system supervised by someone**—has to own all of that.

There is already empirical evidence that humans remain heavily involved in maintaining agent-generated software: a 2026 study of 100 popular repositories found human developers performed the large majority of maintenance on AI-generated files. [arXiv](https://arxiv.org/abs/2605.06464?utm_source=chatgpt.com)

So TalkProof's future competitor isn't simply:

> **AI builds software once.**

It becomes:

> **AI builds + tests + observes + upgrades + repairs + secures software continuously.**

**That future competitor is much more dangerous.**

# How many people can do this today?

We should **not invent a number** such as “5 million people can build TalkProof.”

There isn't a reliable dataset measuring that exact capability.

But we can establish the size of the funnel.

SlashData estimated **47.2 million developers worldwide in early 2025**, including about 36.5 million professionals. [SlashData](https://www.slashdata.co/post/global-developer-population-trends-2025-how-many-developers-are-there?utm_source=chatgpt.com)

GitHub reported **180M+ developers/builders** on its platform in 2025, although that is a much broader account/population measure and should not be confused with professional developers. [The GitHub Blog](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/?utm_source=chatgpt.com)

Stack Overflow reports **59% agent usage** in its April 2026 pulse. [Stack Overflow Blog](https://stackoverflow.blog/2026/09/30/getting-ready-for-2026-results-a-look-back-on-developer-survey-findings/?utm_source=chatgpt.com)

And Anthropic analysed roughly **400,000 Claude Code sessions from about 235,000 people**, finding agentic coding spreading beyond conventional software development. [Anthropic](https://www.anthropic.com/research/claude-code-expertise?subjects=announcements\&utm_source=chatgpt.com)

Therefore:

**Tens of millions have access to the skills/tools ecosystem.**

But the number capable of independently creating and safely operating something as broad as TalkProof is **far smaller and currently unknown**.

That's the number our competitive model should estimate rather than pretend we know.

# And this changes TalkProof's moat completely

This may be the biggest strategic consequence.

If TalkProof's moat is:

> “We wrote 60,000 lines of software.”

**There is almost no future moat.**

If the moat is:

> “We integrated Twilio.”

Weakening moat.

If the moat is:

> “We have a dashboard, transcripts and AI summaries.”

Likely commodity.

Even:

> “We support Claude + OpenAI + Gemini.”

Commodity.

The stronger future moat has to move upward:

**Trust/evidence infrastructure** — verifiable evidence lineage that organisations can rely upon.

**Compliance knowledge** — maintained policy/regulatory machinery rather than static code.

**Operational maturity** — years of failure modes, provider behaviour, monitoring and recovery knowledge.

**Interoperability** — provider-neutral adapters and migration without customer lock-in.

**Data/network learning** — if legally/privacy-appropriately achievable.

**Independent verification** — proof useful outside TalkProof itself.

**Configuration depth** — customer can create their version without rebuilding.

**Continuous AI engineering** — TalkProof itself uses agents to keep adapters, tests, security, performance and documentation current.

And potentially most importantly:

> **TalkProof should become easier to configure than to rebuild.**

That's a much stronger answer to AI-generated custom software.

## This needs to become a separate competitive workstream

Your Claude requirement-recovery prompt is directionally right, but after your questions now, I think the eventual competitor analysis needs a dedicated **Build-vs-Buy / AI Builder Threat Model** with at least:

**Builder persona → required skills → AI assistance level → build time → initial cost → recurring infrastructure cost → maintenance cost → human headcount → security/compliance burden → percentage of TalkProof reproducible → quality achievable → 2026 population → 2028 projection → 2030 projection → implications for TalkProof moat.**

That analysis could materially change what we decide is worth building deeply.

Because the real question is no longer:

> **“Can somebody copy TalkProof?”**

They increasingly can.

The question becomes:

> **“When somebody can ask an AI to build a TalkProof-like system, what makes buying and staying with TalkProof still economically and operationally superior?”**

**That is the competitor question I think we were missing.**
