## Mandatory findings

### F01 — BLOCKER: `restore()` bypasses transaction mode and scope

`InMemoryOrganisationRepository.restore`, `InMemoryPrincipalRepository.restore`, `InMemoryWorkObjectRepository.restore`, `InMemoryEvidenceRepository.restore`, and `InMemoryAuditSink.restore` replace persisted state without `_require_mutation_context()` or an internal rollback capability.

Reproduce both cases before changing code:

```text
P1_JOINED_READ_RESTORE_MUTATION_PERSISTED True
P1_TOP_LEVEL_READ_RESTORE_MUTATION_PERSISTED True
```

Required correction:

1. Make full-state restore transaction-internal, or enforce current WRITE mode plus current-scope coverage on every restore path.
2. Preserve rollback/savepoint operation without exposing a public unguarded mutation channel. A private rollback protocol/capability is preferred; a guard is acceptable only if all rollback paths remain protected and tested.
3. Prove every store rejects restore:
   - outside a transaction;
   - in a top-level READ;
   - in a READ joined into a WRITE;
   - from a nested WRITE scope that did not declare that store;
   - after a caught nested failure.
4. Prove legitimate top-level and nested rollback still restores all declared stores.

### F02 — BLOCKER: public mutating operations are split across transactions

`WorkObjectRegistry.assign`, `resume`, `block`, `unblock`, and `restart_after_rework` perform validation/read work before entering `_transition()`'s write transaction. `block()` can persist stale `blocked_from` after a valid interleaving commit.

Reproduce before changing code:

```text
P2_STATE_AT_WRITE_WAS_ASSIGNABLE True
P2_STALE_BLOCKED_FROM READY
P2_EXPECTED_BLOCKED_FROM ASSIGNABLE
```

Required correction:

1. Each public mutating operation must execute its complete bind/read/precondition/mutation/audit sequence inside exactly one `UnitOfWork.run` callback.
2. `block()` must derive `blocked_from` from the aggregate loaded inside that transaction, not from a prior read.
3. `unblock`, `resume`, and `restart_after_rework` must evaluate their operation-specific preconditions inside the same write transaction.
4. `assign()` must perform assignee membership validation inside the same write transaction as aggregate transition and audit.
5. Add deterministic interleaving regressions for all five operations, not only `block()`.
6. Add a test inventory that enumerates every public kernel mutation and proves its one-transaction boundary.

### F03 — BLOCKER: raw enum values bypass critical evidence policy

`WorkObject.__post_init__` does not enforce runtime enum types. `create(..., risk_level="CRITICAL")` stores a string. `CriticalWorkEvidencePolicy` uses identity against `RiskLevel.CRITICAL`, so the raw string is treated as non-critical and completes without evidence.

Reproduce before changing code:

```text
P3_RAW_CRITICAL_TYPE str 'CRITICAL'
P3_CRITICAL_COMPLETED_WITHOUT_EVIDENCE True
```

Required correction:

1. Enforce canonical runtime types at public/domain boundaries for at least `RiskLevel`, `Priority`, `WorkObjectState`, `PrincipalKind`, and `EvidenceKind`.
2. Use fail-closed policy logic. Invalid domain types returned by a defective adapter must be rejected before disclosure or action.
3. Add exact negative tests for raw strings, foreign enum classes, enum subclasses where relevant, and malformed adapter-returned aggregates.
4. Preserve the project's exact-type trust model where already adopted; do not rely only on static typing.

### F04 — HIGH: rollback misses `BaseException`

`InMemoryUnitOfWork.run` and `InMemoryTenantProvisioner.provision` rollback only in `except Exception`. Cancellation/abort classes derived directly from `BaseException` leave writes committed.

Reproduce before changing code:

```text
P4_BASEEXCEPTION_WRITE_PERSISTED True
```

Required correction:

1. Roll back on `BaseException`, then re-raise the original object unchanged.
2. Test top-level and joined UoW paths, provisioning paths, and caught nested aborts.
3. Include a custom `BaseException` regression and document cancellation/`KeyboardInterrupt` semantics.
