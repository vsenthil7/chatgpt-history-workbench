## What you need to decide

### 1. D-DM1 — which add-on type (open since 11:56, blocks the most)

Google has two add-on types with **incompatible** UI models, and the product was built
assuming a surface that does not exist as described.

| | Workspace add-on | Editor add-on |
| --- | --- | --- |
| HTML/CSS interface | **No** — cards only | Yes |
| Reads the open document | **No** | Yes |
| Apps Script triggers | **No** | Yes |
| Works in Google Forms | **No** | Yes |
| Mobile | Yes | **No** |
| Beyond the Editors (Gmail, Drive, Calendar) | Yes | **No** |

Choosing **Editor** keeps every shipped feature working, and costs mobile plus the
cross-app expansion your roadmap assumes. Choosing **Workspace** reaches mobile and every
host app, and costs **twelve stories** rebuilt as cards plus the form feature dropped or
split.

Nothing downstream can be finalised until this is answered: the scope narrative, the
listing copy, and five story descriptions all change with it. Full analysis in
`ADDON_SURFACE_DECISION.md`.

### 2. DM-F19 / DM-F20 — are these numbers yours or your customers'?

E-sign, filing and form metrics aggregate **across all tenants**, and the support inbox is
unscoped. Correct if they are internal operator views; a data leak the day either is wired
to a per-customer dashboard. A test currently asserts neither is reachable from any HTTP
route, which is what keeps this a decision rather than a live defect.

### 3. Support staffing (R-D13)

The help centre publishes a four-business-hour first-response SLA. Nobody is rostered to
keep it. Three options: staff the stated hours, widen the SLA to what a solo founder can
honour, or publish response expectations without an SLA. Publishing an unstaffed SLA
damages trust more than publishing none.

## What the day actually taught

Worth more than the individual fixes:

**Coverage proves execution, not correctness.** Read-only mode and plan limits were both
fully built, fully tested, and **called from nowhere**. Two behaviours the help centre
promises customers were simply absent from the product, at 100% coverage.

**Authentication is not authorisation.** Adding signed sessions established *who* was
asking. Nothing established *what they were entitled to ask for* — and having the first
made the second look done. That gap allowed cross-tenant template access through a live
route.

**Internal review cannot see platform reality.** Two clean review passes found nothing. A
verification sweep against live Google documentation then found seven findings in seven
checks, three live-blocking: there is no uninstall webhook, Forms cannot POST to a URL,
and our SLO promised throughput the Docs API forbids.

**A plausible reason survives review indefinitely.** One gate exemption was right about its
outcome and wrong about its reason. Exemptions are now tests, with a meta-gate that fails
the build if one is added without verification.

**Sweeps find a class once; gates find it every commit.** The tenant gate, written after a
manual sweep, immediately found five clusters the sweep had missed — because the sweep
checked reads and those were writes.
